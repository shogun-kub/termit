# Termit

[![ci](https://github.com/shogun-kub/termit/actions/workflows/ci.yaml/badge.svg?branch=main)](https://github.com/shogun-kub/termit/actions/workflows/ci.yaml)

[English](README.md) · [Русский](README.ru.md)

Приватная прокси-сеть для небольшой группы людей, у каждого из которых свой VPS.

Каждый участник запускает **termit-uv** на своей Debian-машине. Она превращается в замаскированный
VLESS-поверх-XHTTP узел: сгенерированный сайт-приманка, самостоятельно продлеваемый сертификат и
продуманные правила маршрутизации — проксируемый трафик по умолчанию выходит через сеть Cloudflare
WARP, а собственный трафик машины — никогда. Один небольшой **termit-mn** держит группу в порядке: он
хранит список участников, проверяет каждый узел снаружи и выдаёт каждому владельцу один URL подписки
со всеми живыми узлами, где учётные данные действительны ровно для одной пары узлов.

```
   телефон ─┐                      ┌── ноутбук
            │  VLESS / XHTTP + TLS  │
            ▼                       ▼
   ┌───────────────┐       ┌───────────────┐
   │ Узел A (UV)   │       │ Узел B (UV)   │        по машине на участника,
   │ xray + nginx  │       │ xray + nginx  │        сайт-приманка, свой сертификат
   │ выход WARP    │       │ выход WARP    │
   └───────┬───────┘       └───────┬───────┘
           └──────────┬────────────┘
                      ▼   синхронизация раз в сутки, TLS 443
             ┌──────────────────┐
             │ MN               │  реестр, проверки, подписки
             │ трафик не несёт  │  админ-CLI через unix-сокет
             └──────────────────┘
```

## Быстрый старт

Сначала сервер управления — узлу нужно к чему-то присоединиться, а не наоборот. Подробно:
[Как устроен Termit](docs/guide/ru/overview.md) → [Как запустить сервер](docs/guide/ru/using-mn.md).

```bash
# на сервере (Debian 13, порты 80/443 свободны, DNS указывает на него)
install -m 0755 termit-mn /usr/bin/termit-mn
mn init --domain mn.example.com --email you@example.com --mode invite
install -m 0644 termit-mn.service /etc/systemd/system/ && systemctl enable --now termit-mn
mn invite create --note "node-a"            # печатает код один раз

# на узле (Debian 13, порты 80/443 свободны, DNS указывает на него)
curl -fsSLO https://github.com/shogun-kub/termit/releases/download/v0.1.0/uv.sh
sh uv.sh --version v0.1.0 --domain node-a.example.com --email you@example.com \
  --mn https://mn.example.com --invite ABCD-EFGH-IJKL
```

Дальше `uv status` печатает URL подписки для клиента, а `mn status` показывает состояние сети.
Установщик сверяет релиз с его `SHA256SUMS` и отказывается ставить то, что проверить не может.

## Что это и чем это не является

**Это** способ для нескольких людей держать несколько прокси-путей, не доверяя коммерческому сервису:
каждый узел принадлежит одному человеку, учётные данные парные, а блокировка одного адреса стоит
одного пути, а не всей сети.

**Это не** VPN-провайдер, не панель для перепродажи и не сеть незнакомцев. Вход по приглашению, каждый
узел принадлежит человеку, которого оператор знает, и ничего не тарифицируется.

Осознанные проектные решения, которые стоит знать до развёртывания:

- **Сервер управления никогда не несёт трафик.** Если он упадёт, установленные соединения продолжат
  работать; остановится только изменение состава сети.
- **WARP используется только для проксируемого трафика.** SSH, сайт-приманка и продление сертификата
  всегда идут своим путём. Termit никогда не трогает маршрутизацию и правила фаервола хоста.
- **Неудачная проверка — не сломанный узел.** Проверка, которая не смогла дать вердикт, оставляет
  состояние узла как есть; из сети его выводит только настоящий отрицательный результат.
- **Никаких секретов в логах и метриках.** В логах идентификаторы узлов; `/metrics` доступен только с
  loopback и не содержит инвентаря.

## Состояние

`v0.1.0` выпущен. M1–M4 реализованы и проверены на приёмочной лабе из трёх машин (Debian 13 в
непривилегированных контейнерах), конвейер релиза собирает проверенные артефакты под linux/amd64 и
linux/arm64. Релизы публикуются как **pre-release**, пока не проведён первый production-проход — см.
[чего ещё нет](#чего-ещё-нет).

## Требования

| | |
|---|---|
| Среда | Debian 13 (trixie), amd64 или arm64, systemd, root |
| Порты | 80 и 443 доступны из интернета на каждой машине |
| DNS | по имени на узел и одно для сервера, указывающие на нужную машину |
| Сертификат | выпускается автоматически по ACME (по умолчанию Let's Encrypt) |
| Сборка | Go 1.27.3 или новее; `CGO_ENABLED=0`, зависимостей с cgo нет |

## Сборка и тесты

```bash
go build ./cmd/... ./internal/...                 # оба бинаря
go test ./cmd/... ./internal/...                  # юнит-тесты
go vet ./cmd/... ./internal/...
gofmt -l cmd internal deploy test                 # должно быть пусто

go run ./deploy/release --version v0.1.0 --out dist   # каталог релиза, как его собирает CI
```

Шаблоны пакетов указаны явно намеренно: `references/` содержит сторонний Go-код внутри дерева
модуля, и `./...` скомпилировал бы его.

Приёмка идёт на настоящих машинах по SSH — три Debian-машины (один сервер, два узла), при
необходимости четвёртая для теста сети:

```bash
export TERMIT_LAB_MN=root@mn.example.lan          # и остальное из AGENTS.md §4.3
go test -tags=lab ./test/lab -v -timeout 30m
```

Без этих переменных набор пропускается: это ручной гейт, а не часть `go test ./cmd/...
./internal/...`. CI гоняет gofmt, vet, линтер, юнит-набор с `-race`, кросс-сборку, тесты сборщика
релиза и `govulncheck`.

## Чего ещё нет

- **Production-прохода**: всё, кроме WARP, проверено на лабе — ACME против Pebble, TLS, сеть из трёх
  узлов, обновления, восстановление — но первая установка с реальным доменом и Let's Encrypt и
  настоящий телефон за подпиской всё ещё ручной проход, который кто-то должен выполнить. Именно он
  превращает pre-release в релиз.
- **WARP через настоящий туннель**: на лабе нет `/dev/net/tun`, поэтому набор доказывает отказ,
  сгенерированный маршрут, fail-open (трафик идёт напрямую, когда туннель упал) и возврат к
  прямому выходу; установка, регистрация и подключение требуют KVM-виртуалки или привилегированного
  контейнера.
- **Обновления админ-токена**: токен создаётся один раз в `mn init` и хранится хешем; отдельной
  команды для этого ещё нет, поэтому утёкший токен означает пересборку реестра.
- **Docker Compose для разработки** без лабораторного железа.
