# Termit

[![ci](https://github.com/shogun-kub/termit/actions/workflows/ci.yaml/badge.svg?branch=main)](https://github.com/shogun-kub/termit/actions/workflows/ci.yaml)

[English](README.md) · [Русский](README.ru.md)

Приватная прокси-сеть для небольшой группы людей, у каждого из которых свой VPS.

Каждый участник запускает **termit-uv** на своей Debian-машине. Она превращается в замаскированный
VLESS-поверх-XHTTP узел: сгенерированный сайт-приманка, автоматически продлеваемый сертификат и
продуманные правила маршрутизации — проксируемый трафик по умолчанию выходит через сеть Cloudflare
WARP, а собственный трафик машины — никогда. Один небольшой **termit-mn** держит группу в порядке: он
хранит список участников, проверяет каждый узел снаружи и выдаёт каждому владельцу один URL подписки
со всеми живыми узлами; в нём учётные данные действительны ровно для одной пары узлов.

```
   телефон ─┐                      ┌── ноутбук
            │  VLESS / XHTTP + TLS  │
            ▼                       ▼
   ┌───────────────┐       ┌───────────────┐
   │ Узел A (UV)   │       │ Узел B (UV)   │        по машине на участника,
   │ xray + nginx  │       │ xray + nginx  │        сайт-приманка, свой сертификат
   │ выход WARP    │       │ выход WARP    │
   └───────┬───────┘       └───────┬───────┘
           └──────────┬────────────┘
                      ▼   синхронизация раз в сутки, TLS 443
             ┌──────────────────┐
             │ MN               │  реестр, проверки, подписки
             │ трафик не несёт  │  админ-CLI через unix-сокет
             └──────────────────┘
```

При желании узел отдаёт **тот же сертификат ещё и по QUIC** — Hysteria2 на UDP/443, по умолчанию
выключено, — для участников, чья сеть лучше обходится с UDP, чем с TCP. Трафик всё равно уходит через
WARP-туннель узла: он входит в то же ядро, а не обходит его.

## Быстрый старт

Сначала сервер управления — узлу нужно к чему-то присоединиться, а не наоборот. Самый короткий путь —
[Быстрый старт](docs/guide/ru/quickstart.md); объяснение — в [Как устроен Termit](docs/guide/ru/overview.md), а у
сервера своя страница: [Как запустить сервер](docs/guide/ru/using-mn.md).

```bash
# на сервере (Debian 13, порты 80/443 свободны, DNS указывает на него)
wget -q https://github.com/shogun-kub/termit/releases/latest/download/mn.sh
sh mn.sh --domain mn.example.com --email you@example.com   # --version v0.4.1 закрепляет релиз
termit-mn invite create --note "node-a"                    # печатает код один раз

# на узле (Debian 13, порты 80/443 свободны, DNS указывает на него)
wget -q https://github.com/shogun-kub/termit/releases/latest/download/uv.sh
sh uv.sh --wizard
```

`wget` входит в стандартную установку Debian 13; если у вас есть `curl`, `curl -fsSLO <тот же URL>`
работает так же, и сами установщики качают любым из них.

Мастер спросит имя узла, адрес сервера — вместе с префиксом API, который напечатал `init`, — и код
приглашения. Дальше `termit-uv status` печатает URL подписки для клиента, а `termit-mn status` показывает
состояние сети. Установщик сверяет релиз с его `SHA256SUMS` и отказывается ставить то, что проверить не
может.

## Что это и чем это не является

**Это** способ для нескольких людей держать несколько прокси-путей, не доверяя коммерческому сервису:
каждый узел принадлежит одному человеку, учётные данные парные, а блокировка одного адреса стоит
одного пути, а не всей сети.

**Это не** коммерческий туннельный сервис, не панель для перепродажи и не сеть незнакомцев. Вход по
приглашению, каждый узел принадлежит человеку, которого оператор знает, и ничего не тарифицируется.

Осознанные проектные решения, которые стоит знать до развёртывания:

- **Сервер управления никогда не несёт трафик.** Если он упадёт, установленные соединения продолжат
  работать; остановится только изменение состава сети.
- **WARP используется только для проксируемого трафика.** SSH, сайт-приманка и продление сертификата
  всегда идут своим путём. Termit никогда не трогает маршрутизацию, а его фаервол — по желанию: одна
  таблица nftables существует только после того, как кто-то набрал `termit-uv firewall on`, и `off`
  возвращает хост ровно в прежнее состояние.
- **Неудачная проверка — не сломанный узел.** Проверка, которая не смогла дать вердикт, оставляет
  состояние узла как есть; из сети его выводит только настоящий отрицательный результат.
- **Никаких секретов в логах и метриках.** В логах — идентификаторы узлов; `/metrics` доступен только с
  loopback и не содержит инвентаря.

## Состояние

`v0.4.1` — последний выпуск. M1–M5 реализованы и проверены на приёмочной лабе из трёх машин (Debian 13 в
непривилегированных контейнерах), конвейер релиза собирает проверенные артефакты под linux/amd64 и
linux/arm64. С `0.4.0` туннель WARP живёт внутри ядра прокси, а не в отдельном сервисе, поэтому ему не
нужен `/dev/net/tun`, а `warp.family` решает, какое семейство адресов выходит через него. Проходы за
релизами записаны в [`docs/IMPLEMENTATION_PLAN.md`](docs/IMPLEMENTATION_PLAN.md) (M5.8 для `0.3.2`,
§11.9 для `0.4.0`): три боевые машины — сервер управления в контейнере и две ноды за настоящими
доменами, — фаервол хоста подтверждён и пережил перезагрузку, движок банов и блок-лист работают, выход
через WARP проверен по собственному trace Cloudflare, страница владельца открывается по TLS, телефонное
приложение прогоняет трафик через обе ноды. У `v0.3.2` и её предшественников — свои разделы того же
чейнджлога. См. [чего ещё нет](#чего-ещё-нет).

## Требования

| | |
|---|---|
| Среда | Debian 13 (trixie), amd64 или arm64, systemd, root |
| Чем скачивать | `wget` (входит в Debian 13; `curl -fsSLO <url>` тоже работает, если установлен) |
| Порты | 80 и 443 доступны из интернета на каждой машине |
| DNS | по имени на каждый узел и на сервер, каждое указывает на нужную машину |
| Сертификат | выпускается автоматически по ACME (по умолчанию Let's Encrypt) |
| Сборка | Go 1.27.4 или новее; `CGO_ENABLED=0`, зависимостей с cgo нет |

## Сборка и тесты

```bash
go build ./cmd/... ./internal/...                 # оба бинаря
go test ./cmd/... ./internal/...                  # юнит-тесты
go vet ./cmd/... ./internal/...
gofmt -l cmd internal deploy test                 # должно быть пусто

go run ./deploy/release --version v0.4.1 --out dist   # каталог релиза, как его собирает CI
```

Шаблоны пакетов указаны явно намеренно: `references/` содержит сторонний Go-код внутри дерева
модуля, и `./...` скомпилировал бы его.

Приёмка идёт на настоящих машинах по SSH — три Debian-машины (один сервер, два узла), при
необходимости четвёртая для теста сети:

```bash
export TERMIT_LAB_MN=root@mn.example.lan          # и остальное из AGENTS.md §4.3
go test -tags=lab ./test/lab -v -timeout 30m
```

Без этих переменных набор пропускается: это ручная проверка, а не часть `go test ./cmd/...
./internal/...`. CI прогоняет gofmt, vet, линтер, юнит-набор с `-race`, кросс-сборку, тесты сборщика
релиза и `govulncheck`.

## Чего ещё нет

- **WARP через транспорт `proxy`**: на лабе нет `/dev/net/tun`, поэтому набор покрывает транспорт по
  умолчанию — `wireguard`, которому устройство не нужно; установка и подключение сайдкара `warp-cli`
  требуют KVM-виртуалки или привилегированного контейнера.
- **Docker Compose для разработки** без лабораторного железа.
