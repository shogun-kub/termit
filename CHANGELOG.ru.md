# Журнал изменений

Что изменилось в каждом выпуске — для тех, кто Termit эксплуатирует. Сверху — свежее; `0.1.1`
готовилась, но не вышла: её работа вошла в `0.2.0`.

## 0.2.0 — 2026-11-10

Выпуск, который делает сервер управления менее заметным, а интерактивные меню — рабочими: API под
собственным путём, собственный маскировочный сайт и токен, который можно менять, не редактируя юниты.

### Добавлено

- **Настраиваемый префикс API.** `termit-mn init` при свежей установке выбирает случайный `api_prefix`,
  печатает его, а `termit-mn status` показывает в строке `api:`. Префикс входит в `mn.url`, поэтому узел,
  зарегистрированный по напечатанному URL, сразу попадает в API; `--api-prefix` задаёт его вручную.
  `/sub/<token>` и `/metrics` остаются на своих путях — клиентам и сборщикам метрик не нужно знать префикс.
- **Маскировочный сайт на сервере управления.** Тот же генератор, что и на узлах (`internal/decoy`),
  отдаётся из памяти, выбирается через `decoy.template` (по умолчанию `portal`), seed создаётся один раз
  и хранится в базе. Неизвестные пути получают собственную 404 сайта: проверяющий видит правдоподобный
  сайт, а не голый сервер.
- **Смена админ-токена.** `termit-mn admin rotate` выпускает новый токен, печатает его один раз или пишет
  в файл `0600` по `--token-out`. Меняется тот токен, которым вызвавший аутентифицировался, так что
  ротация никогда не становится способом забрать чужой доступ. Старый токен перестаёт работать
  немедленно — все таймеры и скрипты, которые его носят, придётся обновить.
- **Админ-токен из файла.** `--token-file <путь>` у каждой админ-команды и у меню сервера; переменная
  `TERMIT_MN_ADMIN_TOKEN_FILE` делает то же из окружения. Файл — это один секрет, который надо беречь,
  вместо переменной в каждой оболочке.
- **Интерактивные меню.** `termit-uv menu` и `termit-mn menu`, а также голые бинарники на терминале.
  Каждый пункт запускает ту самую командную строку, которую написал бы скрипт, на общем фронтенде
  (`internal/termui`) с вопросами, подтверждениями и цветом.
- **`docs/MN-API.md`** — справочник по API сервера: пути и префикс, формы запросов и ответов, коды
  проблем, маскировочный сайт, `/metrics` и операции админ-сокета.

### Изменено

- **`uv.sh --mn` теперь доходит и до `init`, а не только до `enroll`.** Адрес записывается в `mn.url`,
  который агент читает на каждом цикле; раньше документированная установка регистрировала узел, который
  затем не мог синхронизироваться. `mn.url` ещё и проверяется: абсолютный `http(s)`-адрес с хостом, без
  query и фрагмента.
- **`termit-mn uv list` показывает настоящую сборку агента.** В колонке версии стояла версия API (`1`);
  теперь там `termit-uv v0.2.0 (<commit>)`, и эта же строка записывается при регистрации.
- **`termit-mn status`** называет префикс API и маскировочный сайт, а `(runtime override)` печатает только
  когда значение действительно отличается от конфигурации.
- **`/` на сервере управления** отвечает маскировочным сайтом, а не 404. В конфигурации, созданной
  `0.1.0`, поля `decoy.template` нет, поэтому там окажется `portal`.
- Бинарники называют себя в командной строке (`termit-uv …`, `termit-mn …`) в usage, help и ошибках,
  а не старыми короткими именами.

### Исправлено

- **Заштампованный релиз не мог зарегистрироваться.** Агент отправлял в `agent_version` свой полный
  баннер — 70+ байт против лимита протокола в 64, — и каждый `enroll` из настоящего релиза падал с
  `agent_version is longer than 64 characters`. Теперь это `<компонент> <версия> (<commit8>)` с обрезкой
  по лимиту. Лаборатория до этого гоняла только незаштампованные сборки `dev`, которые в лимит влезали.
- **Флаги после позиционного аргумента не разбирались** у `termit-mn uv show <узел> --token-file …` и
  `invite revoke <id> --token-file …`: обе команды сообщали, что аргумент-узел не задан.
- **Меню выбрасывали собственные флаги.** `termit-mn menu --token-file …` предупреждало, что токена нет,
  держа его в руках, после чего все админ-действия отказывались работать; `termit-uv menu --config …`
  смотрело и действовало на узел по умолчанию. Теперь оба меню разбирают свои флаги, передают их каждой
  запускаемой команде и отказываются стартовать, если флаги противоречат друг другу.
- Захваченная сессия меню больше не оставляет недописанную строку паузы в выводе.

### Сборка, тесты, выпуск

- CI идёт на `dev` и `release/**`, а не только на `main`; из `dev` и `main` ничего не публикуется.
- Ручная дверь для pre-release: `workflow_dispatch` на ветке `release/<версия>` собирает те же шесть
  файлов и может опубликовать их как `pre-v<версия>-<run>`.
- `AGENTS.md` теперь описывает процесс веток и выпусков.
- Лабораторный набор оставляет сервер под systemd после сценария и переживает одну медленную проверку;
  загрузка подписки доверяет тому же CA, что и узел, — `mn.ca_file` или системному хранилищу.

### Обновление с 0.1.0

- **Перерегистрация не нужна.** В конфигурации `0.1.0` нет `api_prefix`, поэтому сервер продолжает
  обслуживать `/api/v1` — тот путь, который уже используют развёрнутые узлы. `init --api-prefix`
  отказывается менять установленный префикс: его смена означает перерегистрацию каждого узла.
- **Перезапустите сервер и дайте узлам синхронизироваться.** Свою сборку они сообщат на следующем цикле,
  вручную ничего запускать не нужно. После этого `termit-mn uv list` начнёт показывать настоящие версии.
- **`/` начнёт отдавать маскировочный сайт**, когда сервер поднимется. Если нужен другой архетип,
  задайте `decoy.template` до перезапуска.
- Всё остальное — пробер, ACME, хранилище сертификатов, схема базы — не менялось; схема по-прежнему
  версии 5.
