# Быстрый старт

Эта страница проведёт вас от двух пустых машин до работающего телефона — примерно за пятнадцать минут.
Она написана для человека, который никогда не настраивал прокси: после каждой команды сказано, что она
делает, и объяснён каждый вопрос, который задаёт установщик.

Нужны две машины. Первая — **сервер**: он хранит список тех, кто в сети, и никогда не несёт трафик.
Вторая — **узел**: именно к нему подключается ваш телефон. Начинайте с сервера: узел не может
вступить в сеть, которой ещё нет.

Если что-то останется непонятным, длинные версии — [Как пользоваться узлом](using-uv.md) и
[Как запустить сервер](using-mn.md).

## Что нужно

| | Сервер | Узел |
|---|---|---|
| Система | Debian 13, вы работаете `root` по SSH | Debian 13, вы работаете `root` по SSH |
| Имя | `mn.example.com` уже указывает на него | `node-a.example.com` уже указывает на него |
| Сеть | порты 80 и 443 открыты в интернет | порты 80 и 443 открыты в интернет |
| Размер | 2 ядра, 2 ГБ RAM | 1 ядро, 1 ГБ RAM |

«Уже указывает» значит, что DNS-запись существует **до** начала установки. Обе машины получают
бесплатный сертификат Let's Encrypt прямо во время установки, а Let's Encrypt выдаёт его только имени,
которое уже резолвится.

Вместо `mn.example.com` и `node-a.example.com` подставляйте свои имена.

## Порядок работы

1. Настроить сервер.
2. Создать на сервере код приглашения.
3. Настроить узел — одна команда, дальше установщик сам задаёт вопросы.
4. Подтвердить узел на сервере.
5. Скопировать одну ссылку в телефон.

## 1. Сервер

Войдите на сервер как `root` и вставьте одну строку. Она скачивает самый свежий релиз, сверяет файл с
опубликованной контрольной суммой, ставит сервер и его systemd-юнит, кладёт рядом prober, нужный
серверу, создаёт конфигурацию, запускает службу и печатает её состояние. `--version v0.4.1` поставит
указанный релиз вместо самого свежего.

```bash
curl -fsSLO "https://github.com/shogun-kub/termit/releases/latest/download/mn.sh" && sh mn.sh --domain mn.example.com --email you@example.com --admin-token-out /etc/termit/mn/admin.token
```

Что подставить вместо примеров:

| | |
|---|---|
| `--domain` | имя сервера, то самое, что уже указывает на эту машину |
| `--email` | ваш адрес; Let's Encrypt пишет на него только если сертификат скоро истечёт |

В выводе важны два значения:

- **`api prefix:`** — короткое случайное слово вроде `/6rfjdqfn5nno`. Запишите его. Узлу понадобится
  полный адрес `https://mn.example.com/6rfjdqfn5nno`, вместе с префиксом.
- **`admin token`** — пароль для всех команд `termit-mn`. `--admin-token-out` кладёт его в
  `/etc/termit/mn/admin.token`, поэтому он не остаётся в истории терминала.

Проверьте, что он жив:

```bash
export TERMIT_MN_ADMIN_TOKEN_FILE=/etc/termit/mn/admin.token
termit-mn status
```

Вы должны увидеть `server:` с вашим доменом, `api:` с префиксом, `prober: ready` и `uptime:`, отличный
от `0s`. Если вместо этого ошибка, сервер ещё не запустился: `systemctl status termit-mn` и
`journalctl -u termit-mn -n 50`.

## 2. Создать код приглашения

Приглашение — одноразовый пропуск, по которому в сеть входит ровно один узел. На каждый узел своё:

```bash
termit-mn invite create --note node-a
```

Код (например `ABCD-EFGH-IJKL`) печатается **один раз**. Скопируйте его сразу — посмотреть позже
не получится.

## 3. Узел

Войдите на узел как `root` и вставьте одну строку. Она скачивает установщик, проверяет релиз,
устанавливает программу узла и переходит к вопросам. Без `--version` ставится самый свежий релиз;
`sh uv.sh --version v0.4.0 --wizard` закрепляет конкретный.

```bash
curl -fsSLO "https://github.com/shogun-kub/termit/releases/latest/download/uv.sh" && sh uv.sh --wizard
```

Вопросы по порядку и что на них отвечать:

| Установщик спрашивает | Введите это | Когда выбрать другое |
|---|---|---|
| `Язык / Language` | `ru` или `en` — на этом языке будут остальные вопросы | никогда |
| `Домен (имя в DNS, указывающее на эту машину)` | `node-a.example.com` | — без него нельзя |
| `Адрес для центра сертификации (необязательно)` | `you@example.com` | — придёт предупреждение, если сертификат скоро истечёт |
| `Сайт-приманка` | нажмите `Enter` (`portal`) | `product` — другая обычная страница по адресу узла |
| `Выход (all, selected, off)` | `all` — всё проксируемое уходит через Cloudflare | `off`, если не хотите пускать трафик через Cloudflare или хостинг его блокирует; `selected`, если через Cloudflare должны ходить только отдельные сайты |
| `Закрыть узел (да/нет) [y/N]` | `y`, если вы используете эту машину только как узел Termit | `n` или `Enter`, если на машине есть другие нужные вам сервисы (межсетевой экран закроет к ним доступ) или у вас уже настроен свой файрволл |
| `Код приглашения от оператора сервера` | код из шага 2 | `Enter` — пропустить и остаться одиночным узлом |
| `Адрес сервера управления` | `https://mn.example.com/6rfjdqfn5nno` — полный адрес, с префиксом из шага 1 | — обязателен, если ввели код приглашения |
| `Устанавливать узел сейчас?` | `y` или `Enter` | `n` сохранит ответы и ничего не запустит; вернитесь к `termit-uv wizard`, когда будете готовы |

На вопросы да/нет принимаются `y` и `n`, а также `д` и `н`. `Enter` — ответ по умолчанию: он с большой буквы в скобках, как `[y/N]`.

Дальше установщик минуту-две работает сам: ставит ядро прокси, получает сертификат, собирает страницу-приманку, запускает службы и вступает в сеть. Последние строки скажут, что получилось.

Все ответы запоминаются. Если связь оборвалась на середине, запустите `termit-uv wizard` ещё раз — он
продолжит с того места, где остановился.

## 4. Подтвердить узел

Вернитесь на сервер: узел ждёт вашего решения (это и есть режим `invite+approval` по умолчанию):

```bash
termit-mn uv list
termit-mn uv approve node-a.example.com
```

После этого узел показывается как `active` — можно переходить к шагу 5.

## 5. Подключить телефон

На узле напечатайте ссылку:

```bash
termit-uv status
```

Скопируйте строку, которая начинается с `subscribe:`, и откройте её в HAPP или в любом клиенте,
который умеет VLESS с XHTTP. Приложение само прочитает ссылку и добавит подключение: больше ничего
вставлять не нужно, пароля нет.

## Если что-то не работает

| Что вы видите | Что это значит | Что делать |
|---|---|---|
| `invalid invite` или «код уже использован» | код потрачен или истёк | создайте новый на сервере: `termit-mn invite create --note node-a` |
| `no such host` или узел не видит сервер | неверный адрес, префикс или DNS | сверьте адрес с `termit-mn status` и поправьте в `/etc/termit/uv/config.yaml` |
| падает шаг с сертификатом | DNS-запись узла ещё не резолвится или порт 80 закрыт | проверьте с другой машины `getent hosts node-a.example.com`, затем запустите `termit-uv init` |
| установщик остановился на середине | ничего не сломано, просто не всё сделано | запустите `termit-uv wizard` снова — ответы сохранены |
| узел остаётся `pending` на сервере | это режим `invite+approval` по умолчанию | шаг 4 |

Всё остальное: `termit-uv doctor` печатает отчёт, а [Если что-то пошло не так](troubleshooting.md)
перечисляет обычные отказы.

## Сохраните три вещи

| Что | Где | Почему важно |
|---|---|---|
| админский токен | `/etc/termit/mn/admin.token` | нужен каждой команде `termit-mn`; `termit-mn admin rotate` его меняет |
| мастер-ключ | `/etc/termit/mn/master.key` | без него база не соберёт ни одного пароля — и сбросить его нельзя |
| база данных | `/var/lib/termit/mn/termit.db` | ваша сеть: узлы, ссылки, приглашения |

Скопируйте все три в надёжное место и подальше от самого сервера. Копия базы без мастер-ключа — файл,
который нельзя использовать.
