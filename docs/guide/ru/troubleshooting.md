# Если что-то пошло не так

[English](../troubleshooting.md) · [Русский](troubleshooting.md)

Обычно ничего не ломается: агент просыпается раз в сутки, сервер проверяет каждый узел по своему
расписанию, сертификаты продлеваются сами. Когда это перестаёт быть правдой, смотреть нужно в таком
порядке.

## Три команды для начала

```bash
termit-uv doctor                  # на узле: здоровье машины и узла, по строке на проверку
termit-uv status                  # идентичность, сертификат, пиры, синхронизация, WARP
termit-mn status                  # на сервере: prober, очередь, сертификат, таблица узлов
```

`termit-uv doctor` печатает подсказку рядом с каждой неудачной проверкой, а `termit-mn uv show <узел>` на сервере
показывает последнюю проверку и последнюю самопроверку вместе — так видно, «сломалась машина» или
«сломан путь до неё». Дальше: `journalctl -u termit-uv-agent` на узле и `journalctl -u termit-mn` на
сервере.

## Прочитать до паники

- **`unknown` — это не отказ.** Проверка, которая не смогла выполниться — prober упал, DNS на сервере
  сломан, таймаут — ничего не меняет. Узлы сохраняют состояние, пиры продолжают работать. Сеть, где
  все проверки `unknown`, — слепая, а не мёртвая: чинить нужно наблюдателя.
- **`pending` — это нормально.** В режиме `invite+approval` узел ждёт оператора. Он не сломан, и
  переустанавливать его не нужно.
- **`direct` — это не авария.** При включённом WARP и fail-open (туннель упал — трафик идёт
  напрямую, так по умолчанию) мёртвый туннель значит, что проксируемый трафик выходит с вашего
  адреса. Всё работает, адрес просто ваш.
- **Повторный запуск безопасен.** Каждый шаг установки идемпотентен: `termit-uv init` ещё раз доводит
  состояние до нужного и не перегенерирует ни идентичность, ни учётные данные, ни сертификаты.

## Установка сервера

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `termit-mn init` отказывает: `domain is required` | нет `--domain` | передайте имя, которое резолвится на эту машину |
| `termit-mn serve` выходит: `cert: listen on :80` | порт 80 занят | освободите его (`ss -lntp`) или задайте `acme.challenge_listen` и пробросьте порт |
| `termit-mn serve` выходит с ошибкой ACME | DNS ещё не указывает сюда, или порт 80 закрыт | проверьте `dig +short mn.example.com` и доступность порта снаружи |
| `termit-mn serve` выходит: `cannot read the master key` | `/etc/termit/mn/master.key` отсутствует или недоступен | восстановите из резервной копии — без него реестр бесполезен |
| `termit-mn status` говорит `cannot reach the server at …` | сервис не запущен или сокет переехал | `systemctl status termit-mn`, затем `admin_socket` в конфигурации |
| команды `termit-mn` требуют `an admin token is required` | токена нет нигде | экспортируйте `TERMIT_MN_ADMIN_TOKEN` или передайте `--token` либо `--token-file` |
| `termit-mn` отклоняет файл токена: `is mode 0644` | файл читаем группой или всеми | `chmod 600` — файл с токеном, который читают другие, это утёкшие учётные данные |
| `termit-mn` отклоняет файл токена: `owned by uid N` | файл принадлежит другому пользователю, который может его переписать | `chown` на того, кто запускает команды (`root` на сервере), или создайте файл от его имени |
| `termit-mn` отклоняет `--token` вместе с `--token-file` | два креденшела сразу | передайте один: явный флаг никогда не перебивается догадкой |
| таймер или скрипт внезапно говорит `the admin token is not valid` | кто-то обновил токен | возьмите новый там, куда его записали (`--token-out`), или обновите ещё раз из шелла, где он есть |
| `termit-mn admin rotate` говорит `the admin token is not valid` | для обновления нужен текущий токен, а этот уже не он | найдите работающий токен; если не работает ни один — восстановление по процедуре удаления строки в руководстве по эксплуатации |
| после обновления узлы и таймеры работают, а `termit-mn` — нет | обновление заменило креденшел CLI, а не сети: узлы используют агентские ключи и подписки, а не админ-токены | обновите админ-токен только там, где он хранится |
| узел говорит `the server has no API at https://…/enroll` | в его `mn.url` нет префикса API сервера — по голому домену API не живёт | скопируйте URL из `termit-mn status` (строка `api:`) или из вывода `init`; проверка — `termit-uv sync --check` |
| все узлы разом потеряли связь, сервер жив | на сервере сменили префикс, а узлам не сказали | обновите `mn.url` на каждом узле и перезапустите агента; порядок — в `OPERATIONS.md` §3.1 |
| команды `termit-mn` говорят `the admin token is not valid` | не тот токен, или база восстановлена без таблицы `admin` | используйте токен, который напечатал `termit-mn init` |

## Вступление узла

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `termit-uv init` остановился на `ports` | на 80/443 уже что-то слушает | остановите это и повторите `termit-uv init` |
| `termit-uv init` остановился на `dns` | запись пока не резолвится сюда | поправьте DNS; самой установке он не нужен, вступлению — да |
| `termit-uv init` остановился на `certificate` | порт 80 недоступен из интернета или DNS неверен | проверьте и то и другое снаружи; `termit-uv init --only certificate` повторит только этот шаг |
| `termit-uv enroll` → `dns_mismatch` | домен резолвится в другое место, или запрос шёл через прокси | поправьте A/AAAA и повторите: сервер сравнивает запись с адресом, с которого пришёл запрос |
| `termit-uv enroll` → `invalid_invite` | код с опечаткой, отозван, истёк или израсходован | `termit-mn invite list` на сервере, создайте новый |
| `termit-uv enroll` → `domain_taken` | запись с таким доменом уже есть | `termit-mn uv show <домен>`; удалите старую запись или возьмите другое имя |
| `termit-uv enroll` → `rate_limited` | десять неудачных попыток за пятнадцать минут с одного адреса | подождите и повторите |
| узел остаётся `pending` | режим `invite+approval` | `termit-mn uv approve <узел>` на сервере |
| `termit-uv enroll` → ошибка TLS | сертификат сервера ещё не доверен узлу | проверьте `termit-uv doctor` → `acme` и что часы на узле верны |

## Ежедневная работа

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| узел `unavailable`, хотя ручная проверка проходит | prober не может до него добраться | `termit-mn uv show` покажет класс; проверьте `prober.xray_binary` и собственный выход сервера |
| `termit-mn status` пишет `prober: unavailable — every check reports unknown` | не удалось создать рабочий процесс prober | прочитайте причину в строке, поправьте `prober.xray_binary`, перезапустите `termit-mn`; узлы остаются как были |
| в `termit-mn status` растёт `queue: N due` | планировщик не успевает | `journalctl -u termit-mn`; зависший prober видно здесь раньше, чем меняется состояние узла |
| узел `blocked` сразу после обновления | сертификат заменили, а сервер ещё помнил старый | следующая синхронизация принесёт новый лист; если остался `blocked` — `termit-uv unblock` |
| список пиров устарел | суточная синхронизация ещё не прошла (она раз в сутки, так задумано) | `termit-uv sync` |
| `termit-uv sync --check` выходит с кодом 4 | набор клиентов в ядре расходится с серверным | `termit-uv sync` |
| в `termit-uv status` старый `last sync` | агент не работает | `systemctl status termit-uv-agent`, `journalctl -u termit-uv-agent` |
| узел пропал после перезагрузки | юниты не включены | `termit-uv init` включит и запустит их снова |

## Сертификаты

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `termit-uv doctor` → `certificate` warn/fail | продление опаздывает или сломано | `termit-uv renew-cert`; журнал `termit-uv-renew.service` скажет почему |
| сертификат истёк | продление долго не могло достучаться до CA | `termit-uv renew-cert --force` после проверки DNS и порта 80 |
| сертификат сервера истёк | шестичасовое продление всё время падало | журнал `termit-mn` называет ошибку ACME; старый сертификат остаётся в работе до выпуска нового, поэтому чинить нужно путь до CA, а не перезапуск |
| `termit-uv renew-cert` → challenge failed | порт 80 недоступен или DNS уехал | поправьте и повторите |

## Выход в интернет и WARP

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `termit-uv status` показывает `warp: … direct` | WARP упал, fail-open делает своё дело | `termit-uv warp status`, затем `journalctl -u warp-cli`; трафик всё равно работает |
| `termit-uv warp status` показывает `not-installed` | узел ставили с `--no-warp` или пакет удалили | `termit-uv init` или `termit-uv warp mode all` установит и зарегистрирует |
| `termit-uv warp status` показывает `unavailable` | машина не умеет WARP: нет `/dev/net/tun` или нет пакета под архитектуру | чинить нечего — причина напечатана; узел работает и выходит напрямую |
| `termit-uv warp mode` → `start-limit-hit` | слишком много перезапусков за пять минут | `systemctl reset-failed termit-xray termit-uv-agent`, затем повторить |

## Подписки и клиенты

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| подписка отдаёт `404` | токен обновили или он с опечаткой | `termit-uv status` покажет актуальный URL; `termit-mn sub rotate` выпустит новый |
| клиент показывает старых пиров | он не обновился | обновите вручную; URL несёт `ETag`, поэтому кэширующий клиент стоит одного `304` |
| клиент подключается, но трафика нет | учётные данные узла сменились (машину переустанавливали или переносили), или узел `blocked` | `termit-mn uv show <узел>`; заблокированный узел выпадает из всех подписок |
| клиент пишет `unknown version: 72`, и не проходит ни одно соединение | в его ядре нет XHTTP, он свалился в обычный VLESS; узел ответил `HTTP/1.1 400`, и клиент прочитал `H` (72) как версию VLESS | нужен клиент на Xray (Happ, v2rayNG, v2rayN, NekoRay) или `podkop-engine`; стоковый sing-box, Hiddify и Streisand этот транспорт не умеют |
| у клиента не проходит его собственный «тест URL», а сайты открываются | тест ходит на `cp.cloudflare.com`, который сбрасывает `HEAD` по обычному HTTP | поставьте в тесте `https://www.gstatic.com/generate_204` |
| соединения встают лишь часть времени, на всех портах, а узел чист | пакеты теряются между сетью клиента и провайдером узла | направление покажут `ss -tan state syn-recv` и `nstat` на узле; рецепт — `OPERATIONS.md` §16.1 |
| URL подписки утёк | это учётные данные | `termit-mn sub rotate <узел> --domain <MN>`; старый URL сразу перестанет работать |

## Как просить помощи

Соберите это и вставьте в issue — отвечает на девять вопросов из десяти и не содержит учётных данных:

```bash
termit-uv version; termit-uv status; termit-uv doctor
journalctl -u termit-uv-agent -n 100 --no-pager
# на сервере
termit-mn version; termit-mn status
termit-mn uv show <этот узел>
journalctl -u termit-mn -n 100 --no-pager
```

Никогда не присылайте `state.json`, `/etc/termit/uv/config.yaml`, мастер-ключ и админ-токен: в них
учётные данные. Если у вас просят конфигурацию, пришлите вывод
`sed -E 's/(key|token|uuid|secret)[^:]*: .*/\1: <redacted>/I' /etc/termit/uv/config.yaml`.
