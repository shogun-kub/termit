# Как устроен Termit

[English](../overview.md) · [Русский](overview.md)

Termit превращает несколько личных VPS в одну приватную прокси-сеть, состояние которой владельцы
могут проверить сами. У каждого участника свой сервер; никому не нужно доверять чужой машине
ничего, кроме трафика, который он сам через неё отправляет.

## Идея

Коммерческий VPN просит верить, что оператор не ведёт логов, что его нельзя заблокировать и что он
будет работать в следующем году. Свой прокси решает проблему доверия и приносит проблему хуже: один
адрес, один сервер, легко опознаётся как прокси и легко блокируется.

Termit размазывает этот риск по небольшой группе. У каждого владельца свой узел; для любого, кто его
щупает, узел выглядит обычным HTTPS-сайтом; узлы знают общий список участников, поэтому клиент
каждого владельца получает несколько путей в один и тот же интернет. А поскольку узлы принадлежат
разным людям, блокировка одного адреса стоит одного пути, а не всей сети.

Сложность любой такой сети — учёт: кто участник, жив ли его узел, какие учётные данные нужны каждой
паре. Этим занимается небольшой **сервер управления (MN)** — ещё одна машина, принадлежащая тому,
кто готов её держать. MN никогда не проксирует трафик. Он ведёт список участников, проверяет каждый
узел снаружи и выдаёт каждому владельцу один URL подписки со всеми живыми узлами.

## Как всё связано

```
     ваш телефон / ноутбук                  телефон друга
              │                                      │
              │  VLESS поверх XHTTP + TLS            │
              ▼                                      ▼
   ┌──────────────────────┐              ┌──────────────────────┐
   │ Узел A (UV)          │              │ Узел B (UV)          │
   │ ваш VPS              │              │ его VPS              │
   │ xray + nginx         │              │ xray + nginx         │
   │ сайт-приманка        │              │ сайт-приманка        │
   │ выход через WARP     │              │ выход через WARP     │
   └──────────┬───────────┘              └──────────┬───────────┘
              │                                     │
              │   синхронизация раз в сутки, TLS 443│
              └──────────────────┬──────────────────┘
                                 ▼
                    ┌───────────────────────────┐
                    │ MN — сервер управления     │
                    │ реестр узлов, проверки,    │
                    │ подписки; трафик не несёт  │
                    └───────────────────────────┘
```

Три свойства, которые стоит заметить:

- **MN — не прокси.** Пользовательский трафик через него не идёт. Если он упадёт, установленные
  соединения продолжают работать; останавливается только изменение состава сети.
- **Учётные данные — парные.** Узел A общается с узлом B по данным, действительным только для этой
  пары. Всё, что A выдаст клиенту для B, работает для B и ни для чего больше.
- **Проксируемый трафик не обязан выходить с вашего адреса.** С включённым WARP (по умолчанию)
  трафик узла выходит через сеть Cloudflare, поэтому приложение, спрашивающее «с какого я адреса?»,
  видит общий адрес Cloudflare, а не сервер, который можно найти. Прямой трафик — SSH, сайт-приманка,
  обновление сертификата — в этот туннель не попадает.

## Для кого это

Вы — небольшая группа людей, у которых уже есть или скоро будет по Debian-машине (хватает VPS за
3–5 евро в месяц). Вы хотите прокси, который не коммерческий сервис и не одна точка отказа, и вам
нормально работать в терминале.

Это **не** коммерческий VPN-продукт, не панель для перепродажи и не сеть незнакомцев: вход по
приглашению, и каждый узел принадлежит человеку, которого оператор знает.

## Что нужно до начала

| | Сервер управления | Каждый узел |
|---|---|---|
| Машина | Debian 13 (trixie), amd64 или arm64 | Debian 13 (trixie), amd64 или arm64 |
| Ресурсы | 2 vCPU, 2 ГБ RAM, 10 ГБ диска | 1 vCPU, 1 ГБ RAM, 10 ГБ диска |
| Доступ | root по SSH | root по SSH |
| Сеть | публичный IPv4 или IPv6, порты **80** и **443** свободны | публичный IPv4 или IPv6, порты **80** и **443** свободны |
| Имя | одно DNS-имя (`mn.example.com`) на этот адрес | по одному DNS-имени на узел (`node1.example.com`) |
| Сертификат | выпускается автоматически через Let's Encrypt | выпускается автоматически через Let's Encrypt |

Порт 80 нужен для проверки при выпуске сертификата, 443 — для самого сервиса. Оба должны быть
доступны из интернета; машина за CGNAT узлом быть не может.

## Порядок установки

**Да — сначала сервер управления.** Узел можно установить и отдельно (`termit-uv init` сервер не нужен), но
вступить в сеть до появления MN нельзя: код приглашения выдаёт сервер, при вступлении сервер
проверяет узел, а URL подписки, который использует телефон, отдаёт тоже он.

```
1. MN          termit-mn init → systemd → termit-mn status показывает "nodes: 0"
2. приглашение termit-mn invite create --note "node-a"   → ABCD-EFGH-IJKL
3. узел        uv.sh (или termit-uv init) → termit-uv enroll --invite ABCD-EFGH-IJKL
4. одобрение   только в режиме invite+approval: termit-mn uv approve node-a.example.com
5. клиент      termit-uv status → URL подписки → вставить в приложение на телефоне
```

На шаге 3 важна DNS-запись: при вступлении сервер сравнивает адрес, с которого пришёл запрос, с
A/AAAA-записью домена узла — поэтому запись должна указывать на машину **до** вступления. Сертификат
выпускается во время `termit-uv init`, для него нужен свободный порт 80 и уже работающая запись.

Всё после шага 5 происходит само. Узел раз в сутки просыпается, проверяет себя и синхронизирует
состав сети, а сервер проверяет каждый узел по своему расписанию. Вмешиваться нужно, только когда
что-то сломалось.

## Что вы получаете

| Возможность | Что это даёт |
|---|---|
| **URL подписки** | один адрес на узел, внутри — все живые узлы с парными учётными данными; подходит любому клиенту, который понимает подписку `vless://`, плюс профиль sing-box по адресу `<url>/json` |
| **Замаскированный узел** | на 443 отдаётся сгенерированный сайт: запрос без нужного пути получает сайт, а не ошибку прокси |
| **Выход через WARP** (по умолчанию) | проксируемый трафик выходит через сеть Cloudflare, адрес общий, а не ваш; можно переключить на прямой выход или ограничить отдельными доменами |
| **Проверки** | сервер проверяет каждый узел через туннель, его сертификат и приманку, и убирает узел из сети только при настоящей ошибке |
| **Свои устройства** | `termit-uv device add` создаёт локальных клиентов для телефона, ноутбука, роутера — они живут только на вашем узле и никуда не передаются |
| **Перенос узла** | узел можно перевести на новый домен или пересобрать на новой машине, не потеряв место в сети |
| **Поверхность оператора** | дашборд `termit-mn status`, endpoint `/metrics` только на loopback и история проверок по каждому узлу |
| **Резервные копии** | одна команда на сервере; состояние узла — один файл |

## Слова, которые встречаются в этом руководстве

| Термин | Значение |
|---|---|
| **UV**, узел | *termit-uv*, бинарь на сервере участника: установщик, агент и CLI |
| **MN** | *termit-mn*, сервер управления: реестр, проверки, подписки, админ-CLI |
| **peer** (пир) | другой узел сети, как его видит этот узел |
| **парные учётные данные** | пара UUID/путь, действительная ровно между двумя узлами |
| **подписка** | URL, по которому клиент получает текущий список пиров |
| **код приглашения** | одноразовый (или на несколько использований) код для вступления узла |
| **состояние** | `pending`, `active`, `unavailable`, `blocked`, `removed` — что сервер думает об узле |
| **приманка** | сгенерированный сайт, который узел отдаёт всем, кто пришёл без нужного пути |
