# Обновление меша

Termit обновляется изнутри: сервер заменяет свой бинарник, а узел берёт выпуск, который назвал его
сервер. Эти две команды — `termit-mn update` и `termit-uv upgrade` — появились в 0.7.0, поэтому сами
себя до неё не обновят: меш на 0.6.0 или старше переезжает теми же установочными скриптами, которыми его
ставили. Сервер идёт первым, и пока вы идёте, смешанный меш (0.6.0 и 0.7.0) продолжает работать:
`api_version` у обоих 1, а контракт по сети — дополняющий.

## С 0.6.0 на 0.7.0

### Сервер

```bash
wget -qO mn.sh https://github.com/shogun-kub/termit/releases/download/v0.7.0/mn.sh
sh mn.sh --version v0.7.0
termit-mn version
termit-mn status
```

`mn.sh` сверяет бинарник с `SHA256SUMS` выпуска, заменяет `/usr/bin/termit-mn`, прогоняет `init` по
существующей конфигурации и перезапускает юнит. База, мастер-ключ, админский токен и сертификат не
трогаются. Если сервер важен, сначала сделайте бэкап: `termit-mn backup` (архив ложится в
`/var/lib/termit/mn/backups/`).

### Каждый узел

```bash
wget -qO uv.sh https://github.com/shogun-kub/termit/releases/download/v0.7.0/uv.sh
sh uv.sh --version v0.7.0 --no-enroll
termit-uv version
termit-uv doctor
termit-uv sync
```

`--no-enroll` сохраняет зачисление. `init` переписывает то, что просит конфигурация — юниты, vhost,
конфиг ядра, заглушку, — и никогда не перегенерирует личность, сертификат, учётные данные или ссылки
клиентов, так что телефоны продолжают работать. `termit-uv sync` сообщает серверу, что узел теперь на
0.7.0: вид меша читает сборку агента из синхронизации.

Если `uv.sh` предупреждает, что применённая таблица фаервола собрана без UDP/443, таблица старше
конфигурации: `termit-uv firewall status` называет разошедшиеся поля, а `termit-uv firewall on`
перерисовывает её.

### Проверка меша

```bash
termit-mn uv list      # у каждого узла: termit-uv v0.7.0
```

## Дальше

Дальше обе стороны обновляются сами. Сначала сервер:

```bash
termit-mn update --check   # отстаёт ли этот сервер от новейшего выпуска?
termit-mn update --apply   # скачать, проверить, заменить, перезапустить
```

затем на каждом узле:

```bash
termit-uv sync            # узнать сборку сервера
termit-uv upgrade --check # что установил бы прогон
termit-uv upgrade         # скачать, проверить, заменить, свести
termit-uv sync            # сообщить серверу, что теперь на узле
```

Колонка `AGENT` в `termit-mn uv list` берёт новую сборку из синхронизации узла — поэтому блок ею и
заканчивается. `--apply` оставляет работающий бинарник в `/usr/bin/termit-mn.prev` и возвращает его, если перезапуск
не удался; `upgrade` делает то же с `termit-uv.prev` и даёт новому бинарнику прогнать `init`, потому что
новый выпуск — тот, кто знает, что ему нужно. Узел на пре-релизной сборке команда откажется обновлять:
назовите выпуск (`termit-uv upgrade --to v0.7.0`) или перезапустите скрипт — узел идёт за выпусками, но
никогда за сборками `p<n>`.

## Если что-то пошло не так

- **Узел после обновления хуже.** Верните предыдущий выпуск тем же скриптом:
  `sh uv.sh --version v0.6.0 --no-enroll`. Схема состояния в обоих выпусках — 1, а конфигурация читается
  одинаково, поэтому старый бинарник загрузит то, что записал новый.
- **Сервер не поднялся после `mn.sh`.** `systemctl restart termit-mn`, прочитайте журнал; если база шагнула
  вперёд, восстановите бэкап, снятый до обновления (`termit-mn restore`).
- **`termit-mn update` или `termit-uv upgrade` неизвестна.** Этот бинарник — 0.6.0 или старше: используйте
  скрипты, как выше.
