# Обновление меша

[English](../updating.md) · [Русский](updating.md)

Сервер и узлы обновляются отдельно: сервер заменяет свой бинарник, а узел ставит выпуск, о котором
сообщил его сервер. Сервер всегда идёт первым. Наполовину обновлённый меш продолжает работать:
`api_version` в 0.6.0 и 0.7.0 одинаковый.

`termit-mn update` и `termit-uv upgrade` появились в 0.7.0, поэтому у установки 0.6.0 их ещё нет.
Чтобы попасть на 0.7.0, запустите те же установочные скрипты с `--version v0.7.0`. Начиная с 0.7.0 ту
же работу делают эти две команды.

0.5.1 и 0.5.2 идут тем же путём, что и 0.6.0. Их конфигурация — подмножество конфигурации 0.7.0 (новые
ключи необязательны), а схема состояния — 1 у всех трёх, так что руками править нечего. На лабе обе
версии переехали на 0.7.0, не потеряв ни личность, ни ссылки клиентов.

## С 0.6.0 на 0.7.0

### Сервер

```bash
wget -qO mn.sh https://github.com/shogun-kub/termit/releases/download/v0.7.0/mn.sh
sh mn.sh --version v0.7.0
termit-mn version
termit-mn status
```

`mn.sh` сверяет бинарник с `SHA256SUMS` выпуска, заменяет `/usr/bin/termit-mn`, прогоняет `init` с
существующей конфигурацией и перезапускает юнит. База, мастер-ключ, админский токен и сертификат
остаются как были. Если сервер вам важен, сначала выполните `termit-mn backup`: архив ляжет в
`/var/lib/termit/mn/backups/`.

### Каждый узел

```bash
wget -qO uv.sh https://github.com/shogun-kub/termit/releases/download/v0.7.0/uv.sh
sh uv.sh --version v0.7.0 --no-enroll
termit-uv version
termit-uv doctor
termit-uv sync
```

`--no-enroll` оставляет узел в меше. `init` переписывает то, что просит конфигурация: юниты, vhost,
конфиг ядра, заглушку. Личность, сертификат, учётные данные и ссылки клиентов он не перегенерирует,
поэтому телефоны продолжают работать. `termit-uv sync` сообщает серверу, какая сборка стоит на узле:
вид меша читает её из синхронизации.

### Если в таблице фаервола нет UDP/443

`uv.sh` предупреждает об этом, когда `init` собирает таблицу, которая не совпадает с применённой: та
была собрана до включения Hysteria2, и загрузка вернула её из старой записи. Пропавший `udp dport 443` —
не просто закрытый порт: QUIC-пакеты каждого клиента попадают в счётчик сканов, движок банов выносит
клиенту бан, и перестаёт работать даже TLS-профиль.

На узле это чинится так:

```bash
termit-uv firewall status      # что в силе и какие поля разошлись
termit-uv firewall on          # собрать таблицу из конфигурации
termit-uv firewall confirm     # оставить её — без этого через пять минут откатится
```

`firewall on` собирает то, что просит конфигурация, поэтому в `security.firewall.udp_ports` должен быть
443 — без него `init` не включит Hysteria2.

`on` применяет таблицу на пять минут и напоминает проверить, что SSH и 443 отвечают; `confirm` оставляет
её навсегда. Следующая загрузка вернёт уже подтверждённую таблицу — предупреждение уйдёт вместе с ней.
Если клиента уже забанили, снимите бан по адресу:

```bash
termit-uv bans list            # бан с причиной "scan" — это клиент, которого не пустила таблица
termit-uv bans unban <ip>
```

Полная процедура — в [руководстве по эксплуатации](../../RUNBOOK.ru.md), §12 шаг 8 и §13.

### Проверка меша

```bash
termit-mn uv list      # у каждого узла: termit-uv v0.7.0
```

## Дальше

Дальше обе стороны обновляются сами. Сначала сервер:

```bash
termit-mn update --check   # отстаёт ли сервер от новейшего выпуска?
termit-mn update --apply   # скачать, проверить, заменить, перезапустить
```

затем каждый узел:

```bash
termit-uv sync            # узнать сборку сервера
termit-uv upgrade --check # что будет установлено
termit-uv upgrade         # скачать, проверить, заменить, свести конфигурацию
termit-uv sync            # сообщить серверу, что теперь на узле
```

Колонка `AGENT` в `termit-mn uv list` берёт новую сборку из синхронизации узла — поэтому блок ею и
заканчивается. `--apply` оставляет старый бинарник в `/usr/bin/termit-mn.prev` и возвращает его, если
перезапуск не удался. `upgrade` делает то же с `termit-uv.prev`, а затем даёт новому бинарнику прогнать
`init`: новый выпуск знает, что ему нужно. Узел на пре-релизной сборке обновлять откажется — так
задумано. Назовите выпуск (`termit-uv upgrade --to v0.7.0`) или запустите скрипт ещё раз: узел идёт за
выпусками, но не за сборками `p<n>`.

## Если что-то пошло не так

- **Узел после обновления хуже.** Верните предыдущий выпуск тем же скриптом:
  `sh uv.sh --version v0.6.0 --no-enroll`. Схема состояния у обоих выпусков — 1, конфигурация читается
  одинаково, поэтому старый бинарник загрузит то, что записал новый.
- **Сервер не поднялся после `mn.sh`.** Выполните `systemctl restart termit-mn` и прочитайте журнал.
  Если база шагнула вперёд, восстановите бэкап, снятый до обновления (`termit-mn restore`).
- **`termit-mn update` или `termit-uv upgrade` неизвестна.** Этот бинарник — 0.6.0 или старше.
  Используйте скрипты, как выше.
