# Интерактивное меню

[English](../menu.md) · [Русский](menu.md)

У обоих бинарей есть меню. Оно нужно потому, что команд много, а флаги не запоминаются:
`termit-uv renew-cert --force`, `termit-mn uv block <узел> --reason <текст>`. На терминале можно выбрать из списка,
и меню само задаст те вопросы, на которые отвечали бы флаги.

Меню **не** вторая реализация чего бы то ни было — вот что важно. Каждый пункт
собирает командную строку и запускает ту же команду, которую запустил бы скрипт, — в том же процессе,
через тот же код. Поэтому пункт меню и его флаги не могут разойтись, а всё, что делает меню, можно
сделать командой — и процитировать в отчёте об ошибке.

## Как открыть

```bash
termit-uv                  # на терминале — меню
termit-mn                  # на терминале — меню
termit-uv menu             # явно, даже если вывод перенаправлен
termit-mn menu
```

Без аргументов и с терминалом на stdin и stdout бинарь открывает меню. Во всех остальных случаях — в
скрипте, в cron, при перенаправленном выводе — он остаётся тем, чем был: текстом справки и кодом
выхода 2. Это сделано намеренно. Если команду случайно вызвали из скрипта, а она
превращается в приглашение ко вводу, это зависание, а не удобство.

```
┌──────────────────────────────────────────────────────────────────────┐
│  Termit — node                                                       │
│  termit-uv v0.4.1 (commit …, built …, api 1)                         │
│                                                                      │
│    domain        node-a.example.com                                  │
│    identity      3f9c1a2b                                            │
│    peer path     e9438a65                                            │
│    ✔ installed                                                       │
│                                                                      │
│    1   status               identity, certificate, peers, sync, WARP │
│    2   doctor               check the host and the node, change…     │
│    …                                                                 │
│    q   quit                                                          │
│                                                                      │
│  choose [1-21, q]:                                                   │
└──────────────────────────────────────────────────────────────────────┘
```

Отвечать можно номером или названием: `3` и `install or converge` — один и тот же ответ, потому что
вы смотрите именно на название. Пустая строка принимает значение по умолчанию, показанное в
скобках; `q` выходит; если ответ ни с чем не совпал, меню переспрашивает, а не завершает работу: меню,
которое падает от опечатки, — меню, которому не доверяют. Вопросы внутри пункта подчиняются тому же
правилу: значение, без которого команда не может работать, переспрашивается, если его оставили пустым,
а ответ «да/нет», который не является ни тем, ни другим, тоже переспрашивается — опечатка не отвечает за
вас. Закрытый stdin (труба, которая закончилась) завершает сессию штатно, с кодом 0.

## Меню узла (`termit-uv`)

| Пункт | Что делает | Какую команду запускает |
|---|---|---|
| status | домен, отпечатки идентичности, сертификат, пиры, последняя и следующая синхронизация, WARP | `termit-uv status` |
| doctor | диагностика хоста и узла; ничего не меняет | `termit-uv doctor` |
| диагностика соединений | снимает счётчики TCP: теряет узел или путь? | `termit-uv net` |
| install or converge | первый запуск спросит домен, email и WARP; последующие только перепроверяют | `termit-uv init …` |
| setup wizard | вся первая установка в виде вопросов; ответы сохраняются между запусками | `termit-uv wizard` |
| client options | закрытая страница со всеми ссылками для клиентов и её адрес | `termit-uv options` |
| join the mesh | спросит адрес сервера и код приглашения | `termit-uv enroll …` |
| lift a block | попросить сервер проверить узел и вернуть его в строй | `termit-uv unblock` |
| move to another domain | перенести узел на новый домен (сценарий C) | `termit-uv migrate --relocate …` |
| sync now | получить список пиров сейчас, не дожидаясь суточной синхронизации | `termit-uv sync` |
| check drift | показать, совпадает ли работающее ядро с сервером | `termit-uv sync --check` |
| devices | список, добавление и удаление собственных устройств узла | `termit-uv device …` |
| print vless URI | URI собственного устройства этого узла | `termit-uv uri` |
| egress (WARP) | показать, переключить `all`, `off`, `selected` или сменить устройство | `termit-uv warp …` |
| firewall | таблица хоста: состояние, on, off, confirm, refresh, restore | `termit-uv firewall …` |
| bans | кого заблокировал движок банов и ваши собственные постоянные блокировки | `termit-uv bans …` |
| guard | работает ли движок блокировок и сколько он заблокировал | `termit-uv guard status` |
| certificate | продлить сейчас; при желании — принудительно перевыпустить | `termit-uv renew-cert [--force]` |
| decoy site | перегенерировать сайт-приманку, при желании с другим архетипом | `termit-uv renew-site …` |
| uninstall | спрашивает дважды и называет, что заберёт `--purge` | `termit-uv uninstall [--purge]` |
| help | все команды и флаги | `termit-uv help` |

## Меню сервера (`termit-mn`)

| Пункт | Что делает | Какую команду запускает |
|---|---|---|
| status | сервер, база, prober, таблица узлов | `termit-mn status` |
| nodes | список, показ, approve, reject, block, unblock, удаление, reissue, agent key, forget | `termit-mn uv …` |
| invites | создание, список и отзыв кодов | `termit-mn invite …` |
| check now | вся сеть или один узел | `termit-mn check now --all` / `termit-mn check now <узел>` |
| policy | показать пороги или изменить один | `termit-mn policy …` |
| subscription | обновить токен подписки узла | `termit-mn sub rotate <узел>` |
| admin token | заменить админский токен, которым вы работаете | `termit-mn admin rotate` |
| backup | снять согласованный снимок | `termit-mn backup` |
| restore from a snapshot | вернуть базу и сертификаты; спросит архив и напомнит, что сервер должен быть остановлен | `termit-mn restore --from … --force` |
| firewall | таблица хоста: состояние, on, off, confirm, refresh, restore | `termit-mn firewall …` |
| bans | кого заблокировал движок банов и ваши собственные постоянные блокировки | `termit-mn bans …` |
| guard | работает ли движок блокировок и сколько он заблокировал | `termit-mn guard status` |
| help | все команды и флаги | `termit-mn help` |

Меню сервера — это надстройка над админ-CLI, поэтому ему нужно то же, что и админ-CLI: работающий
сервер и админ-токен. Отдайте токен самому меню, и каждая запущенная им команда его унаследует:

```bash
termit-mn menu --token-file /etc/termit/mn/admin.token
```

В шапке написано, на каком именно админ-токене работает сессия (`admin token from --token-file …`, из
`TERMIT_MN_ADMIN_TOKEN` или из `TERMIT_MN_ADMIN_TOKEN_FILE`), а если его нет — сказано прямо, и
админ-действия откажутся работать — так скажет сам CLI. `--config` и `--socket` работают так же.
Локальные команды — `backup`, `restore`, `firewall`, `bans`, `guard` — читают хост, а не API, ни одного
из этих флагов не принимают, и меню их им не передаёт.

Меню узла по той же причине принимает `--config`: `termit-uv menu --config /path/to/config.yaml`
смотрит и действует на тот узел, а не на узел по умолчанию.

Запуска сервера в меню намеренно нет. `termit-mn serve` запускает systemd-юнит, а лог собирает journald;
меню, запускающее долгоживущий сервер в переднем плане, спрятало бы этот лог за экраном меню. По той же
причине в меню нет ещё четырёх команд: `termit-uv agent` и `guard run` — это циклы, которыми владеют
юниты; `firewall rollback` — команда таймера отката, и её собственная справка так и говорит; `version`
написана в шапке каждого экрана. `termit-mn init` тоже не в меню: меню разговаривает с работающим
сервером, а когда нужна эта команда, сервера ещё нет. Всё остальное, что принимает бинарник, в меню
есть, и `help` печатает полный список, — а поскольку каждый пункт запускает ту командную строку,
которую печатает, пункт не может сделать того, чего не может CLI.

## Цвет

Цвет включается, когда stdout — терминал. `NO_COLOR=1` (любое значение) или `TERM=dumb` его
выключают, а перенаправленный вывод не раскрашивается никогда — сохранённый отчёт читается как
обычный текст. Без цвета экран ещё и не очищается, поэтому записанная сессия читается как
последовательность разделов, а не как одна страница, переписанная заново.

## Когда меню не нужно

- **При установке без человека.** У `uv.sh`, `termit-uv init` и `termit-mn init` флаги существуют не просто так: на
  вопрос во время установки автоматический запуск ответить не может, и зависание посреди
  подготовки узла хуже ошибки. Меню — для человека на терминале, которому проще выбрать, чем
  вспоминать флаг.
- **В скриптах и аудитах.** Каждое действие меню печатает командную строку, которую запускает, —
  именно для того, чтобы её можно было скопировать в скрипт или в тикет. Используйте команду, а не
  меню.
- **Через нестабильное соединение.** Меню не хранит состояние между экранами, поэтому оборванная
  SSH-сессия ничего не теряет, но долгое действие (установка, продление сертификата) лучше запускать
  под `systemd-run` или в `tmux`, где вывод переживёт обрыв.
