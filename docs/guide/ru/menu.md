# Интерактивное меню

[English](../menu.md) · [Русский](menu.md)

У обоих бинарей есть меню. Оно нужно потому, что команд много, а флаги не запоминаются:
`termit-uv renew-cert --force`, `termit-mn uv block <узел> --reason <текст>`. На терминале можно выбрать из списка,
и меню само задаст те вопросы, на которые отвечали бы флаги.

Меню **не** вторая реализация чего бы то ни было — вот что важно. Каждый пункт
собирает командную строку и запускает ту же команду, которую запустил бы скрипт, — в том же процессе,
через тот же код. Поэтому пункт меню и его флаги не могут разойтись, а всё, что делает меню, можно
сделать командой — и процитировать в отчёте об ошибке.

## Как открыть

```bash
termit-uv                  # на терминале — меню
termit-mn                  # на терминале — меню
termit-uv menu             # явно, даже если вывод перенаправлен
termit-mn menu
```

Без аргументов и с терминалом на stdin и stdout бинарь открывает меню. Во всех остальных случаях — в
скрипте, в cron, при перенаправленном выводе — он остаётся тем, чем был: текстом справки и кодом
выхода 2. Это сделано намеренно. Если команду случайно вызвали из скрипта, а она
превращается в приглашение ко вводу, это зависание, а не удобство.

```
┌──────────────────────────────────────────────────────────────────────┐
│  Termit — node                                                       │
│  termit-uv vX.Y.Z (commit …, built …, api 1)                         │
│                                                                      │
│    domain        node-a.example.com                                  │
│    identity      3f9c1a2b                                            │
│    peer path     e9438a65                                            │
│    serves        TLS/443 only                                        │
│    egress        all via wireguard                                   │
│    server        vX.Y.Z (this node is behind)                        │
│    peers         3 (1 degraded)                                      │
│    sync          2h ago                                              │
│    ✔ installed                                                       │
│                                                                      │
│    1   Состояние            что это за узел и всё ли с ним в пор…    │
│    2   Сеть                 счётчики, WARP, второй транспорт         │
│    …                                                                 │
│    8   Справка              все команды и флаги                      │
│    q   quit                                                          │
│                                                                      │
│  choose [1-8, q]:                                                    │
└──────────────────────────────────────────────────────────────────────┘
```

`vX.Y.Z` в шапке — сборка этого узла (например, `v0.7.0`), а строка `server` — сборка сервера
управления.

Отвечать можно номером или названием: `1` и `Состояние` — один и тот же ответ, потому что
вы смотрите именно на название. Пустая строка принимает значение по умолчанию, показанное в
скобках; `q` выходит; если ответ ни с чем не совпал, меню переспрашивает, а не завершает работу: меню,
которое падает от опечатки, — меню, которому не доверяют. Вопросы внутри пункта подчиняются тому же
правилу: значение, без которого команда не может работать, переспрашивается, если его оставили пустым,
а ответ «да/нет», который не «да» и не «нет», тоже переспрашивается — опечатка не отвечает за
вас. Закрытый stdin (труба, которая закончилась) завершает сессию штатно, с кодом 0.

Меню сервера спрашивает, о каком узле речь, показывая прокси-сеть списком: домен запоминается, id — нет.
Отвечайте номером, доменом, id или любой уникальной частью домена — `then5` находит
`then5.bookinet.ru`. Если часть подходит нескольким узлам, вопрос повторится вместе со списком; `0`
отменяет; если сервер недоступен, вопрос говорит это и принимает набранный домен. Вопрос, называющий
то, что уже существует (узел, код приглашения), на пустом ответе отменяет действие и пишет об этом в
подписи; вопрос, задающий новое значение (домен устанавливаемого узла), по-прежнему переспрашивает.

Оба меню — один экран, не больше десяти пунктов на уровень: группа открывает свой экран, заголовок
повторяет, какая это группа, а `0` возвращает на уровень выше. Запоминать нечего: номер, который видно,
это номер, который набирается.

Шапка над пунктами — карточка узла: домен, отпечатки идентичности, транспорты, которые узел несёт, куда
уходит проксируемый трафик, сборка сервера (с пометкой, если узел отстал), какую часть прокси-сети узел
видит и когда синхронизировался. Она собирается из локального состояния на каждом экране и потому ничего не
стоит; остальное — в `Состояние → status`.

## Меню узла (`termit-uv`)

Восемь пунктов, каждый — группа, которая открывает свой экран; `0` возвращает на уровень выше. Каждый
лист печатает команду, которую запускает.

**Состояние** — *что это за узел и всё ли с ним в порядке*

- `status` — домен, отпечатки идентичности, сертификат, пиры, последняя и следующая синхронизация, WARP
- `doctor` — диагностика машины, узла и туннеля тремя группами, с одним итогом; ничего не меняет

**Сеть** — *счётчики, WARP, второй транспорт*

- `net` — снять счётчики TCP: теряет узел или путь?
- `warp` — показать выход, переключить `all`/`off`/`selected` или сменить устройство
- `transport` — включить или выключить Hysteria2 на UDP/443; ответ по умолчанию — то, что узел уже делает

**Клиенты** — *ссылки, страница клиента, устройства*

- `options` — приватная страница со всеми клиентскими ссылками и её адрес
- `uri` — URI собственного устройства этого узла
- `devices` — список, добавление и удаление устройств этого узла

**Прокси-сеть** — *синхронизация, вступление, снятие блокировки*

- `sync` — получить набор пиров сейчас, не дожидаясь суточной синхронизации
- `sync --check` — расходится ли работающее ядро с сервером
- `agent --once` — одна самопроверка и одна синхронизация, не дожидаясь таймера
- `enroll` — вступить в прокси-сеть: адрес сервера и код приглашения
- `unblock` — попросить сервер проверить узел и пустить его обратно

**Защита** — *межсетевой экран, баны, страж*

- `firewall` — таблица хоста: состояние, включить, выключить, подтвердить, обновить, восстановить
- `bans` — адреса, которые забанил страж, и ваши постоянные баны
- `guard status` — работает ли движок банов и сколько заблокировал

**Сайт** — *сертификат и сайт-приманка*

- `renew-cert` — выпустить заново; при желании принудительно
- `renew-site` — перегенерировать сайт, при желании с другим архетипом

**Узел** — *установка, переезд, удаление*

- `init` — установить или сойтись; первый запуск спросит домен, email и WARP
- `wizard` — вся первая установка в виде вопросов; ответы запоминаются
- `upgrade` — поставить релиз, который называет сервер; прошлый бинарник остаётся рядом и возвращается,
  если свестись не удалось. Предлагается, только если сервер назвал релиз, отличный от текущей сборки.
- `migrate --relocate` — перенести узел на другой домен (сценарий C)
- `agentkey --install <file>` — принять ключ от нового ведущего сервера после `termit-mn home handoff`
  (спросит файл и подтверждение; старый ключ перестаёт работать сразу)
- `uninstall` — спрашивает дважды и называет, что заберёт `--purge`

**Справка** — все команды и флаги.

## Меню сервера (`termit-mn`)

Семь пунктов; `0` возвращает на уровень выше.

**Состояние** — *сервер, проверка, пороги, страж*

- `status` — сервер, база, пробник, очередь, сертификат, таблица узлов
- `check now --all` / `check now <узел>` — всю прокси-сеть или один узел
- `policy` — показать пороги или изменить один
- `guard status` — работает ли движок банов и сколько заблокировал

**Узлы** — *прокси-сеть, по одному действию на строку*

- `uv list` — все узлы с доменом, состоянием и последним контактом
- `uv show`, `uv approve`, `uv reject`, `uv block`, `uv unblock`, `uv rm`, `uv reissue`, `uv agentkey`,
  `uv forget` — каждый спрашивает, какой узел, списком прокси-сети, а не id; два разрушительных (`reissue`,
  `forget`) сначала переспрашивают

**Приглашения** — *коды для новых узлов*

- `invite list`, `invite create` (с заметкой), `invite revoke`
- `invite policy` — правило, которое встречает новый узел: код, код и одобрение или ничего; изменение
  вступает в силу после перезапуска сервера, и команда об этом говорит

**Подписка** — *сменить токен подписки узла*

- `sub rotate` — спросит узел и, при желании, публичное имя сервера

**Защита** — *межсетевой экран и баны*

- `firewall` — таблица хоста: состояние, включить, выключить, подтвердить, обновить, восстановить
- `bans` — адреса, которые забанил страж, и ваши постоянные баны

**Обслуживание** — *токен, резервные копии, восстановление*

- `admin rotate` — заменить админский токен, которым вы работаете
- `backup` — снять согласованный снимок
- `restore` — вернуть базу и сертификаты; спросит архив и скажет, что сервер надо остановить
- `update` — поставить свежий опубликованный релиз и перезапустить сервер; спросит, оставит прошлый
  бинарник рядом и вернёт его, если перезапуск не удался
- `update --check` — спросить GitHub, есть ли новее; ничего не устанавливает
- `home handoff` — передать один узел другому серверу в прокси-сети; спросит узел и пира и один раз напечатает
  новый агентский ключ (без него узел не сможет синхронизироваться)
- `home adopt` — принять узлы сервера, который больше не вернётся; спросит пира и откажется, пока тот
  отвечает (это передача, а не спасение)
- `epoch rotate` — ротация всех парных учётных данных прокси-сети; спросит и потребует ответа от каждого пира
  (ротация на половине прокси-сети хуже, чем никакой)

**Справка** — все команды и флаги.
## Чего в меню нет

Из меню доступна каждая команда из справки, кроме перечисленных ниже. Каждая либо запускается юнитом
systemd, либо отвечает на вопрос, которого нет ни на одном экране меню, и это решение, а не недосмотр:

- `termit-uv agent` без `--once`, `termit-uv warp-relay`, `termit-uv guard run`, `termit-mn serve` и
  `termit-mn guard run` — их запускают юниты. `agent --once` в меню есть, пункт «прогнать цикл агента».
- `termit-mn init` — свежий сервер ставит `mn.sh`; меню работает на установленном.
- `firewall rollback` — его запускает таймер отката, и справка самой команды говорит, что она не для
  интерактивного использования.
- `version` — печатается в заголовке над каждым экраном.
- `menu` — это и есть меню.
- `termit-mn uv forget --force` — меню забывает уже удалённый узел после одного подтверждения. `--force`
  стирает копию строки, которую ведёт **другой сервер**: это ремонт прокси-сети, который делают, прочитав, какая
  из двух записей настоящая, поэтому он остаётся в CLI, где id можно процитировать.

`TestEveryDocumentedCommandIsInTheMenuOrExplained` в обоих бинарниках падает, если команды нет ни в меню,
ни в этом списке. Значит, новая опция попадает либо в меню, либо сюда — с причиной.

## Цвет

Цвет включается, когда stdout — терминал. `NO_COLOR=1` (любое значение) или `TERM=dumb` его
выключают, а перенаправленный вывод не раскрашивается никогда — сохранённый отчёт читается как
обычный текст. Без цвета экран ещё и не очищается, поэтому записанная сессия читается как
последовательность разделов, а не как одна страница, переписанная заново.

## Когда меню не нужно

- **При установке без человека.** У `uv.sh`, `termit-uv init` и `termit-mn init` флаги существуют не просто так: на
  вопрос во время установки автоматический запуск ответить не может, и зависание посреди
  подготовки узла хуже ошибки. Меню — для человека на терминале, которому проще выбрать, чем
  вспоминать флаг.
- **В скриптах и аудитах.** Каждое действие меню печатает командную строку, которую запускает, —
  именно для того, чтобы её можно было скопировать в скрипт или в тикет. Используйте команду, а не
  меню.
- **Через нестабильное соединение.** Меню не хранит состояние между экранами, поэтому оборванная
  SSH-сессия ничего не теряет, но долгое действие (установка, продление сертификата) лучше запускать
  под `systemd-run` или в `tmux`, где вывод переживёт обрыв.
