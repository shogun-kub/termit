# Интерактивное меню

[English](../menu.md) · [Русский](menu.md)

У обоих бинарей есть меню. Оно нужно потому, что команд много, а флаги не запоминаются:
`termit-uv renew-cert --force`, `termit-mn uv block <узел> --reason <текст>`. На терминале можно выбрать из списка,
и меню само задаст те вопросы, на которые отвечали бы флаги.

Важно то, чем меню **не** является: это не вторая реализация чего бы то ни было. Каждый пункт
собирает командную строку и запускает ту же команду, которую запустил бы скрипт, — в том же процессе,
через тот же код. Поэтому пункт меню и его флаги не могут разойтись, а всё, что делает меню, можно
сделать командой — и процитировать в багрепорте.

## Как открыть

```bash
termit-uv                  # на терминале — меню
termit-mn                  # на терминале — меню
termit-uv menu             # явно, даже если вывод перенаправлен
termit-mn menu
```

Без аргументов и с терминалом на stdin и stdout бинарь открывает меню. Во всех остальных случаях — в
скрипте, в cron, при перенаправленном выводе — он остаётся тем, чем был: текстом справки и кодом
выхода 2. Это сделано намеренно. Команда, которая превращается в приглашение ко вводу, если её
случайно вызвали из скрипта, — это зависание, а не удобство.

```
┌──────────────────────────────────────────────────────────────────────┐
│  Termit — node                                                       │
│  termit-uv v0.1.0 (commit 8f8cb7c, built 2026-11-09, api 1)          │
│                                                                      │
│    domain        node-a.example.com                                  │
│    identity      3f9c1a2b                                            │
│    peer path     e9438a65                                            │
│    ✔ installed                                                       │
│                                                                      │
│    1   status               identity, certificate, peers, sync, WARP │
│    2   doctor               check the host and the node, change…     │
│    …                                                                 │
│    q   quit                                                          │
│                                                                      │
│  choose [1-13, q]:                                                   │
└──────────────────────────────────────────────────────────────────────┘
```

Отвечать можно номером или названием: `3` и `install or converge` — один и тот же ответ, потому что
название — это то, на что вы смотрите. Пустая строка принимает значение по умолчанию, показанное в
скобках; `q` выходит; ответ, не совпавший ни с чем, переспрашивает, а не завершает работу: меню,
которое падает от опечатки, — меню, которому не доверяют. Закрытый stdin (труба, которая закончилась)
завершает сессию штатно, с кодом 0.

## Меню узла (`termit-uv`)

| Пункт | Что делает | Какую команду запускает |
|---|---|---|
| status | домен, отпечатки идентичности, сертификат, пиры, последняя и следующая синхронизация, WARP | `termit-uv status` |
| doctor | диагностика хоста и узла; ничего не меняет | `termit-uv doctor` |
| install or converge | первый запуск спросит домен, email и WARP; последующие только перепроверяют | `termit-uv init …` |
| join the mesh | спросит адрес сервера и код приглашения | `termit-uv enroll …` |
| sync now | получить список пиров сейчас, не дожидаясь суточной синхронизации | `termit-uv sync` |
| check drift | показать, совпадает ли работающее ядро с сервером | `termit-uv sync --check` |
| devices | список, добавление и удаление собственных устройств узла | `termit-uv device …` |
| print vless URI | URI собственного устройства этого узла | `termit-uv uri` |
| egress (WARP) | показать или переключить `all`, `off`, `selected` | `termit-uv warp …` |
| certificate | продлить сейчас; при желании — принудительно перевыпустить | `termit-uv renew-cert [--force]` |
| decoy site | перегенерировать сайт-приманку, при желании с другим архетипом | `termit-uv renew-site …` |
| uninstall | спрашивает дважды и называет, что заберёт `--purge` | `termit-uv uninstall [--purge]` |
| help | все команды и флаги | `termit-uv help` |

## Меню сервера (`termit-mn`)

| Пункт | Что делает | Какую команду запускает |
|---|---|---|
| status | сервер, база, пробер, таблица узлов | `termit-mn status` |
| nodes | список, показ, approve, reject, block, unblock, удаление | `termit-mn uv …` |
| invites | создание, список и отзыв кодов | `termit-mn invite …` |
| check now | вся сеть или один узел | `termit-mn check --all` / `termit-mn check <узел>` |
| policy | показать пороги или изменить один | `termit-mn policy …` |
| subscription | обновить токен подписки узла | `termit-mn sub rotate <узел>` |
| backup | снять согласованный снимок | `termit-mn backup` |
| help | все команды и флаги | `termit-mn help` |

Меню сервера — это надстройка над админ-CLI, поэтому ему нужно то же, что и админ-CLI: работающий
сервер и админ-токен. Отдайте токен самому меню, и каждая запущенная им команда его унаследует:

```bash
termit-mn menu --token-file /etc/termit/mn/admin.token
```

В шапке написано, на каком именно креденшеле работает сессия (`admin token from --token-file …`, из
`TERMIT_MN_ADMIN_TOKEN` или из `TERMIT_MN_ADMIN_TOKEN_FILE`), а если его нет — сказано прямо, и
админ-действия откажутся работать словами самого CLI. `--config` и `--socket` работают так же.

Меню узла по той же причине принимает `--config`: `termit-uv menu --config /path/to/config.yaml`
смотрит и действует на тот узел, а не на узел по умолчанию.

Запуска сервера в меню намеренно нет. `termit-mn serve` принадлежит systemd-юниту, который собирает его лог;
меню, запускающее долгоживущий сервер в переднем плане, спрятало бы этот лог за экраном меню.

## Цвет

Цвет включается, когда stdout — терминал. `NO_COLOR=1` (любое значение) или `TERM=dumb` его
выключают, а перенаправленный вывод не раскрашивается никогда — сохранённый отчёт читается как
обычный текст. Без цвета экран ещё и не очищается, поэтому записанная сессия читается как
последовательность разделов, а не как одна страница, переписанная поверх себя.

## Когда меню не нужно

- **При установке без человека.** У `uv.sh`, `termit-uv init` и `termit-mn init` флаги существуют не просто так: на
  вопрос в пути установки автоматический запуск ответить не может, и зависание посреди
  подготовленного узла хуже ошибки. Меню — для человека на терминале, которому проще выбрать, чем
  вспоминать флаг.
- **В скриптах и аудитах.** Каждое действие меню печатает командную строку, которую запускает, —
  именно для того, чтобы её можно было скопировать в скрипт или в тикет. Используйте команду, а не
  меню.
- **Через нестабильное соединение.** Меню не хранит состояние между экранами, поэтому оборванная
  SSH-сессия ничего не теряет, — но долгое действие (установка, продление сертификата) лучше запускать
  под `systemd-run` или в `tmux`, где вывод переживёт обрыв.
