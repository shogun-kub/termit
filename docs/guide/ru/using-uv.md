# Как пользоваться узлом (termit-uv)

[English](../using-uv.md) · [Русский](using-uv.md)

Всё, что происходит на вашей машине: установка, вступление в прокси-сеть, подключение телефона и команды,
которые вы реально будете набирать. Если ещё не читали [как устроен
Termit](overview.md) — начните с той страницы: она объясняет, что такое узел и сервер.

Если проще выбрать из списка, чем вспоминать флаги, запустите `termit-uv` без аргументов на узле — это
[интерактивное меню](menu.md), и каждый пункт печатает команду, которую запускает.

Нужно: Debian 13, root, DNS-имя, указывающее на машину, свободные порты 80 и 443, а также код
приглашения от того, кто держит сервер управления ([как запустить сервер](using-mn.md)).

## Перед тем как трогать машину

1. **Направьте DNS на неё.** Создайте запись `A` (и `AAAA`, если есть IPv6) для `node1.example.com`.
   Выпуск сертификата и вступление в прокси-сеть зависят от записи, а при вступлении сервер сравнивает её с
   адресом запроса — поэтому сначала запись и время на то, чтобы она разошлась, а потом всё остальное.
2. **Освободите порты.** На свежем Debian там ничего нет; если машина уже что-то отдаёт, уберите это.
   `ss -lntp | grep -E ':(80|443) '` покажет, что мешает.
3. **Понимайте, что делает WARP.** WARP включён по умолчанию: проксируемый трафик выходит через сеть
   Cloudflare. Если хотите выходить со своего адреса — устанавливайте с `--no-warp`. Больше ничего в
   руководстве не меняется.

## Установка

Скачайте установщик и запустите его — не передавайте URL в шелл через пайп. `wget` есть не всегда: в
минимальном и netinst-образе Debian нет ни его, ни `curl`, поэтому сначала поставьте что-то одно
(`apt-get update && apt-get install -y wget`). `curl -fsSLO <тот же URL>` тоже подойдёт:

```bash
apt-get update && apt-get install -y wget   # только если в образе нет ни curl, ни wget

wget -q https://github.com/shogun-kub/termit/releases/latest/download/uv.sh

sh uv.sh \
  --domain node1.example.com --email you@example.com \
  --mn https://mn.example.com/6rfjdqfn5nno --invite ABCD-EFGH-IJKL
```

Без `--version` скрипт ставит самый свежий опубликованный релиз; `--version vX.Y.Z` закрепляет
названный, а сборка `v<version>p<n>` — это способ тестировщика поставить предрелиз.

`--mn` — это URL, который сервер напечатал при `termit-mn init`, **вместе с префиксом API**:
`https://mn.example.com/6rfjdqfn5nno`, а не голый домен. Префикс — это путь, по которому живёт API, а
узел, которому дали только домен, никуда не достучится (он так и скажет, а не пожалуется на
приглашение).

Скрипт сверяет контрольную сумму релиза по `SHA256SUMS`, ставит `termit-uv`, запускает `termit-uv init`
(он и делает всю работу) и затем `termit-uv enroll` с вашим приглашением. `--mn` попадает в оба шага:
`init --mn` записывает адрес в конфигурацию как `mn.url` — именно его агент читает на каждой
синхронизации, — а `enroll` использует его при вступлении. Если запустить
`termit-uv enroll --mn URL` вручную позже, адрес тоже сохранится в конфигурации, если его там ещё нет.

`--wizard` заменяет флаги вопросами: скрипт ставит бинарник и передаёт терминал `termit-uv wizard`, а тот
спрашивает домен, почту, сервер, приглашение и остальное.

Полезные варианты:

| Задача | Флаг |
|---|---|
| установить и настроить, вступить позже | `--no-enroll` |
| пусть спросит вместо флагов | `--wizard` — ставит бинарник и запускает `termit-uv wizard` |
| посмотреть, что будет, ничего не меняя | `--dry-run` |
| зеркало или локальный каталог вместо GitHub | `--base-url https://mirror.example.com/termit` |
| сверить с известным вам дайджестом | `--sha256 <hex>` (или `--checksum-file SHA256SUMS`) |
| своя сборка, не релиз | поставить бинарник самому и запустить `termit-uv init` |
| отказаться от WARP | `--no-warp`, позже `termit-uv warp mode off` |
| сменить, как WARP несёт трафик | `termit-uv init --warp-transport wireguard` (внутри ядра, TCP и UDP), `usque` (сайдкар MASQUE — вспомогательный процесс рядом с ядром; TCP и UDP, для машины, чей `warp-cli` не умеет UDP) или `proxy` (сайдкар `warp-cli`, только TCP) |
| выбрать, какое семейство выходит через WARP | `termit-uv init --warp-family ipv4` (по умолчанию; назначения другого семейства отклоняются) или `ipv6` — только для WireGuard-транспорта внутри ядра; на MASQUE-сайдкаре не-дефолтное семейство отклоняется |

Непроверенные байты скрипт не ставит. Если он остановился — в сообщении есть файл и ожидаемый дайджест.

### Без скрипта

Две команды, результат тот же:

```bash
install -m 0755 termit-uv /usr/bin/termit-uv
termit-uv init --domain node1.example.com --email you@example.com
```

## Что делает `termit-uv init`

Каждый шаг идемпотентен: если результат шага уже есть, он ничего не делает. Поэтому повторный запуск —
это способ починить частичную установку.

| Шаг | Что делает |
|---|---|
| `preflight` | проверяет root, версию Debian, systemd, архитектуру, часы, свободные порты, DNS, каталог ACME, `/dev/net/tun`, диск, память и `apt` — по строке на проверку, с подсказкой, если что-то не так |
| `user` | создаёт непривилегированного пользователя `termit` |
| `dirs` | `/etc/termit/uv`, `/var/lib/termit/uv`, `/var/www/termit` |
| `packages` | ставит `nginx`, `ca-certificates`, `curl` |
| `warp` | регистрирует WARP-идентичность узла для туннеля; с `--warp-transport proxy` вместо этого ставит и поднимает `cloudflare-warp`; пропускается, если WARP выключен |
| `xray-binary` | скачивает закреплённое прокси-ядро, проверяет SHA-256, устанавливает |
| `identity` | генерирует UUID узла, путь запроса и seed приманки — **один раз и навсегда** |
| `decoy` | генерирует сайт-приманку |
| `xray-config` | пишет конфигурацию ядра и проверяет её через `xray -test` |
| `web` | пишет конфигурацию nginx для узла и проверяет её через `nginx -t` |
| `units` | пишет и включает systemd-юниты и таймер продления |
| `certificate` | получает бесплатный сертификат Let's Encrypt, отвечая на его проверку по порту 80 |
| `start` | запускает ядро, nginx и агента и проверяет, что они держатся |
| `warp-egress` | тянет trace Cloudflare через собственный туннель узла и говорит, откуда вышел; предупреждение, но не отказ |

С включённым QUIC-транспортом в списке появляются ещё две строки — `hysteria-binary` и `hysteria-config`, —
а без него `hysteria-off`, которая ничего не делает, если транспорт никогда не ставился. MASQUE-транспорт
(`--warp-transport usque`) так же добавляет `usque-binary` и `usque-register`, а `usque-off` убирает его с
узла, который им больше не пользуется.

В конце печатаются сводка и отпечаток идентичности. Сообщение об ошибке называет шаг и команду;
`--only <шаг>` перезапускает только его.

## Вступление в прокси-сеть

```bash
termit-uv enroll --invite ABCD-EFGH-IJKL                  # --mn URL, если его нет в конфигурации
termit-uv status                                          # вступили? пиры? сертификат?
```

`termit-uv enroll` сохраняет ключ агента и токен подписки в файл состояния (`0600`, показываются один
раз) и запускает первую синхронизацию. Если сервер в режиме `invite+approval`, узел останется
в `pending`, пока оператор его не одобрит — это нормально, а не ошибка:

```bash
termit-mn uv approve node1.example.com        # на сервере управления
```

## Подключение телефона или ноутбука

Есть две разные вещи, и важно, какая вам нужна:

| | Подписка | Локальное устройство |
|---|---|---|
| Что внутри | этот узел **и все живые пиры** | только этот узел |
| Где живёт | на сервере управления | только на этом узле |
| Как получить | `termit-uv status` печатает URL | `termit-uv device add --label phone` печатает `vless://` |
| Для чего | свой клиент, когда нужна вся прокси-сеть | устройство, которому нужен один узел, или клиент без поддержки подписок |

И то и другое есть на закрытой странице владельца (`termit-uv options`): там собственное устройство
узла, локальные устройства и прокси-сеть, и она перерисовывается сама — при добавлении и удалении
устройства и на каждой синхронизации, включая суточный цикл агента, так что новый или ушедший пир попадает на
страницу без команд. Каждая ссылка на ней несёт оба варианта переключателя фрагментации —
`fragment=…` для Happ и `sb.tls.fragment=1`/`sb.tls.record_fragment=1` для `podkop-engine` и патченных
сборок sing-box, — так что одна и та же ссылка работает в любом из них без правки руками.

Но не в любом клиенте: **Throne** и семейство Nekoray, из которого он вырос, не разбирают ни того, ни
другого — у них фрагментация живёт в своих настройках. В Throne для Android это *изменить профиль →
«TLS Client Hello fragment»* (переключатель с тремя состояниями, по умолчанию «Keep default», рядом
«TLS record fragment»), а чтобы сразу для всех — *Настройки → Пресеты → «TLS Client Hello fragment»* с
реализацией и размером; в десктопной сборке те же три живут в профиле в разделе «TLS Camouflage
Settings». В JSON-форме подписки она есть (`"fragment": true`, `"record_fragment": true`), так что
клиент, который импортирует профиль, а не ссылку, получает её без единого клика.

У каждой строки под кнопкой «копировать» раскрывается QR-код: наведите на него камеру телефона, и клиент
импортирует ссылку — это единственный жест, который у телефона есть, и ради него страница и существует.
Код рисует сам узел, страница не обращается ни к какому внешнему хосту, а секрет в нём тот же, что в
тексте, так что скриншот — такая же утечка, как скопированная ссылка.

Страница заодно отвечает «что делает этот узел» без второй команды: в шапке есть выход
(`egress: all via wireguard`, `off (direct)`, …), а ссылка второго транспорта помечена `(QUIC)` и
подписана «голос и видео» — это тот транспорт, который везёт звонок, и страница — то место, где
владелец оказывается, когда ему это нужно знать.

```bash
termit-uv status
# subscribe:  https://mn.example.com/sub/AbCdEf...
```

Вставьте этот URL в поле «URL подписки» клиента. Нужен клиент, чьё ядро умеет XHTTP: Happ, v2rayNG,
v2rayN, NekoRay (на Xray) или `podkop-engine` на OpenWrt. Стоковый sing-box XHTTP не умеет — он молча
свалится в обычный VLESS, узел ответит ему `400`, и клиент покажет `unknown version: 72` (72 — это `H`,
первый байт `HTTP/1.1`). Для сборок sing-box с патчем XHTTP есть `/json` — тот же список пиров в виде
профиля: селектор, `direct` и приватные диапазоны напрямую.

Клиент сам перечитывает список; когда пир появляется или уходит, достаточно одного обновления. URL —
это секрет: в нём ваши учётные данные. Если он утёк, обновите токен на сервере
(`termit-mn sub rotate node1.example.com --domain mn.example.com`), и старый перестанет работать.

## Второй транспорт поверх QUIC (по желанию)

Узел умеет отдавать свой сертификат ещё и на UDP/443 — через Hysteria2, протокол, сделанный под мобильные
каналы с потерями. Голосовые звонки и видео это чувствуют первыми; обычному просмотру он не нужен, и
ничего не устанавливается, пока вы сами не попросите.

```bash
termit-uv init --hysteria      # поставить и включить; в меню это «Сеть → QUIC-транспорт»
```

Флаг сам записывает блок, который нужен транспорту (`hysteria: {}`), и добавляет `443` в
`security.firewall.udp_ports`: UDP-порт, которого нет в этом списке, попадает в счётчик сканирования ядра,
и защита забанила бы собственный QUIC-трафик владельца. Уже применённую таблицу `init` не трогает —
межсетевой экран применяется только командой `firewall on` — поэтому её надо пересобрать, чтобы порт
стал доступен:

```bash
termit-uv firewall on && termit-uv firewall confirm
```

`init` после этого поставит закреплённый бинарник, напишет `/etc/termit/uv/hysteria.yaml` и запустит
`termit-hysteria` под отдельным непривилегированным пользователем. В конце он синхронизируется: что узел
отдаёт, доходит до сервера только в запросе синхронизации. Дальше:

- `termit-uv uri`, `termit-uv device add` и `termit-uv device list` печатают ссылку `hy2://` рядом с
  `vless://`, с пометкой `(QUIC)`, и то же делает страница из `termit-uv options`;
- подписка с сервера несёт ту же вторую ссылку, а sing-box-профиль получает outbound `hysteria2`;
- транспорт объявляется той синхронизацией, которой заканчивается `init`; `termit-uv sync` делает то же
  вручную, а на сервере настраивать нечего.

Чего это стоит: около 50 МБ памяти, а юнит ограничен 256 МБ; 4–9 % одного ядра на каждые 100 Мбит/с
трафика. Закреплённый релиз упомянут ещё в одной уязвимости, GO-2026-5288, но её запись в базе Go не
проверена и не называет исправленной версии — а в самом advisory (GHSA-9fw6-xgg2-mq9q) последняя
затронутая версия — 2.8.1, исправлено в 2.8.2, тогда как на узле стоит 2.14.0 и сниффинг, без которого
proof of concept не работает, узел не включает. Потолок 256 МБ и `Restart=always` при этом остаются, так
что разнос памяти в транспорте не утащит с собой ни TLS-профиль, ни остальные сервисы узла.

Чтобы выключить, запустите `termit-uv init --no-hysteria`: юнит остановится, отключится и удалится
вместе с конфигурацией и закреплённым бинарником, порт закроется, а следующая синхронизация уберёт
вторую ссылку из подписки.

## Ежедневная работа
```bash
termit-uv status               # идентичность, сертификат, пиры, последняя синхронизация, WARP
termit-uv doctor               # машина, узел и туннель тремя группами, с подсказкой на каждую неудачу
termit-uv doctor --json        # то же машинно-читаемо
termit-uv net                  # счётчики TCP: узел теряет или путь до него?
termit-uv sync                 # привести ядро в соответствие со списком пиров сейчас
termit-uv sync --check         # код 4, если узел разошёлся с сервером; ничего не меняет
termit-uv agent --once         # один полный цикл на переднем плане, для проверки
termit-uv unblock              # попросить сервер перепроверить узел и снять блокировку
```

`termit-uv status`, чтобы понимать, на что смотрите:

```
domain:       node1.example.com
installed:    2026-11-09T18:20:01Z
identity:     a10ceae7
proxy path:   e9438a65
decoy:        portal (seed 5927413a)
local users:  2 (phone, laptop)
core:         xray 26.11.9 at /usr/lib/termit/bin/xray
certificate:  expires 2027-02-08T12:06:44Z (in 89 days)
management:   enrolled 2026-11-10T06:16:10Z
subscribe:    https://mn.example.com/sub/AbCdEf...
peers:        2 (node2.example.com, node3.example.com)
options:      https://node1.example.com/915aa2413e4a124bfed884ca5029c967/
server:       vX.Y.Z
support:      meets the server's minimum vX.Y.Z
last sync:    ok 2026-11-10T14:51:11Z
next sync:    2026-11-11T14:55:13Z
warp:         on (via 104.28.1.1 (AMS))
self-check:   ok 2026-11-10T11:17:04Z
```

`support:` на этом экране — минимальная сборка узла, которую поддерживает сервер (`min_agent_version` в его
конфигурации): узел ниже неё говорит об этом здесь, `termit-uv doctor` предупреждает, а работать ничего не
мешает — лечится командой `termit-uv upgrade`.

Агент синхронизируется в назначенное сервером время плюс свой небольшой сдвиг, проверяет себя (взгляд
узла на интернет), применяет набор пиров и засыпает. Между этими циклами он просыпается с интервалом,
который задаёт сервер (по умолчанию пятнадцать минут, ключ `mesh_poll` в конфигурации сервера), и читает
`healthz`, где лежит дайджест прокси-сети: если прокси-сеть изменилась (узел вступил, ушёл,
заблокирован или переехал), он синхронизируется сразу, так что новый узел появляется у всех в пределах
одного интервала. Свой таймер заводить не нужно: systemd-юниты ставит `termit-uv init`.

## Справочник команд

| Команда | Что делает | Основные флаги |
|---|---|---|
| `termit-uv init` | установить или довести узел до нужного состояния | `--domain`, `--email`, `--locale ru\|en`, `--happ-fragment VALUE`, `--no-warp`, `--warp MODE`, `--warp-selected LIST`, `--dry-run`, `--only`, `--skip`, `--acme-ca`, `--xray-version`, `--xray-download-base`, `--warp-transport wireguard\|usque\|proxy`, `--warp-family ipv4\|ipv6`, `--harden`, `--decoy-template`, `--acme-skip-tls-verify`, `--relocate`, `--agent-key-file` |
| `termit-uv doctor` | диагностика машины, узла и туннеля тремя группами, с одним итоговым вердиктом; ничего не меняет | `--json` |
| `termit-uv net` | отличить плохой путь от больного узла по счётчикам TCP | `--seconds 60`, `--json` |
| `termit-uv status` | идентичность, сертификат, пиры, сборка сервера, синхронизация, WARP | `--json` |
| `termit-uv enroll` | вступить в прокси-сеть: сервер выдаёт узлу идентичность | `--invite`, `--mn`, `--force`, `--no-sync` |
| `termit-uv sync` | синхронизировать пиров сейчас | `--check`, `--dry-run`, `-v` (печатать список пиров) |
| `termit-uv agent` | цикл агента на переднем плане | `--once` |
| `termit-uv device` | локальные устройства на этом узле | `list`, `add --label NAME [--uuid ...]`, `remove NAME` |
| `termit-uv uri` | напечатать `vless://` для этого узла | `--label` |
| `termit-uv options` | собрать закрытую страницу со ссылками для клиентов и напечатать её адрес | `--rotate`, `--quiet` |
| `termit-uv wizard` | провести через первую установку, запоминая ответы; первым делом спросит язык | `--fresh` |
| `termit-uv warp` / `termit-uv warp status` | показать выход | `--json` |
| `termit-uv warp mode` | сменить выход | `off`, `all`, `selected --selected a.example,b.example` |
| `termit-uv warp rotate` | зарегистрировать новое устройство WARP | |
| `termit-uv unblock` | попросить сервер перепроверить и разблокировать | `--domain`, `--vless-url`, `--no-sync` |
| `termit-uv upgrade` | заменить бинарник узла опубликованным релизом | `--to vX.Y.Z` (по умолчанию — версия сервера), `--check`, `--release-base URL` |
| `termit-uv migrate` | перевести узел на новый домен | `--relocate`, `--domain`, `--no-sync` |
| `termit-uv agentkey` | показать идентичность учётных данных узла или принять ключ, который выдал новый ведущий сервер после `home handoff` | `--install FILE` |
| `termit-uv menu` | интерактивное меню: его открывает команда без аргументов на терминале | `--config` |
| `termit-uv warp-relay` | loopback-релей перед MASQUE-сайдкаром; его запускает юнит | |
| `termit-uv renew-cert` | продлить сертификат сейчас | `--force` (перевыпустить, даже если не пора) |
| `termit-uv renew-site` | перегенерировать сайт-приманку | `--template product\|portal`, `--seed`, `--dry-run` |
| `termit-uv uninstall` | убрать то, что создал Termit | `--purge` (ещё конфигурация, состояние, сертификаты, пользователь), `--dry-run` |
| `termit-uv firewall` | межсетевой экран на хосте: `status`, `on`, `off`, `confirm`, `rollback`, `refresh`, `restore` | `--ssh-from`, `--default-deny`, `--dry-run` |
| `termit-uv bans` | что решил движок банов: `list`, `offenders`, `block IP`, `unban IP`, `unblock IP` | |
| `termit-uv guard` | движок банов: `status`, `run --once` | |
| `termit-uv version` | версия сборки и протокола | |

Команды, которые читают конфигурацию, принимают `--config <path>`, а у большинства есть `-v`/`--verbose`.
Необязательная половина защиты — `firewall`, `bans` и `guard` — выключена, пока не попросите; ей посвящена
страница [Защита узла](hardening.md).

## Рецепты

**Перевести узел на новый домен.** Добавьте новую DNS-запись, затем на узле:

```bash
termit-uv init --domain node2.example.com --relocate --agent-key-file /root/agent.key
termit-uv migrate --relocate --domain node2.example.com
```

`termit-uv init --relocate` сохраняет ключ агента (это идентичность узла для сервера), создаёт новую
идентичность для нового имени и не вступает в прокси-сеть; `termit-uv migrate --relocate` просит сервер
проверить новый адрес и заменить запись. Пиры увидят изменение при следующей синхронизации.

**Пересобрать умершую машину.** На сервере `termit-mn uv agentkey node1.example.com` печатает ключ агента
(узел при этом не страдает). На новой машине:

```bash
termit-uv init --domain node1.example.com --agent-key-file /root/agent.key --relocate
termit-uv migrate --relocate
```

**Заменить сайт-приманку.**

```bash
termit-uv renew-site --template product        # product или portal
```

**Сменить выход.**

```bash
termit-uv warp mode off                        # напрямую со своего адреса
termit-uv warp mode all                        # обратно на WARP (по умолчанию)
termit-uv warp mode selected --selected example.com,api.example.org
```

**Удалить узел.** `termit-uv uninstall` убирает юниты, ядро и vhost nginx, останавливает сервисы;
`--purge` дополнительно удаляет конфигурацию, состояние, сертификаты и пользователя `termit`.
Пакеты, которые он ставил, остаются; другие сайты nginx не затрагиваются. На сервере запись
останется, пока оператор не сделает `termit-mn uv rm` — скажите ему, иначе пиры будут видеть
несуществующий узел, пока проверки не начнут падать.

## Где что лежит

| Путь | Содержимое |
|---|---|
| `/etc/termit/uv/config.yaml` | ваша конфигурация — единственный файл, который вы правите |
| `/var/lib/termit/uv/state.json` | идентичность, секреты, токен подписки (`0600`) |
| `/var/lib/termit/uv/` | журнал запусков установки |
| `/usr/lib/termit/bin/xray` | прокси-ядро |
| `/var/www/termit/` | сайт-приманка и каталог ACME-челленджа |
| `/etc/nginx/sites-enabled/termit.conf` | сгенерированный vhost, ссылка на `sites-available/termit.conf` |

Юниты: `termit-xray.service`, `termit-uv-agent.service`, `termit-uv-renew.timer` (сертификат) и
`termit-uv-renew.service`. `systemctl status termit-uv-agent` и
`journalctl -u termit-uv-agent` отвечают на большинство вопросов.
